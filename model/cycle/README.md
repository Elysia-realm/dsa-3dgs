# B0周期与流量模型

该目录用于把功能黄金模型转换为可进行架构比较的周期级模型。

当前B0假设：

- 全局深度计算后使用7-pivot递归分组；
- 不对全体高斯进行完整排序，只保证组间全序；
- 各组投影、精排、SH和块渲染可流水重叠；
- alpha结果进入有限队列；
- 混合通过per-block前驱scoreboard保证顺序；
- 属性流量按FP16模型估算，参数集中在`B0Config`。

## 时间语义

- `*_latency`是单项工作从发射到结果就绪的流水延迟；`*_throughput`决定相邻输入或相邻组的启动间隔。
- 投影、排序和SH单元允许在前一组尚未完成时接收后一组，因此“单元可用时间”按busy/issue周期推进，而“本组完成时间”包含latency。
- 当前排序busy采用补齐到2的幂的Bitonic网络比较次数除以比较器数量的近似值；尚未绑定具体RTL网络与布线时序。
- 光栅任务目前按全局`(gaussian_order, task_id)`发射；不同块可交错混合，同一块由前驱scoreboard严格顺序提交。

## 工作生成和流量边界

- 软件端用精确FP32 alpha/T轨迹判断已完全终止的块，并在任务生成阶段移除这些块；这代表功能正确的跳过上限，不等同于已经实现的硬件反馈时序。
- `candidate_blocks`表示包围盒触达的候选块，`issued_blocks`表示排除全终止块后进入alpha流水的任务。
- DRAM统计目前是模型属性与最终RGB的字节估计；SRAM统计是排序记录、投影特征和图像状态的逻辑访问量，尚未计入bank冲突、burst效率、缓存行填充和控制元数据。
- 报告中的FPS只由假设频率除以模型周期得到，在RTL/真实场景校准前不得作为硬件性能结论。

## 当前验证结论

- 稀疏且块间不重叠的负载没有scoreboard代价。
- 多块密集覆盖可用块间交错隐藏依赖，主要受混合吞吐和有限结果队列约束。
- 单块热点是顺序提交的退化情形，会产生显著scoreboard停顿。
- 合成强遮挡负载说明提前终止可显著减少任务，但百分比只用于验证趋势，不代表真实数据集收益。

这些数字是设计假设，不是综合或实测结果。后续需用RTL和真实模型统计逐项校准。

## R0状态

`r0.py`实现第一版保守可重构模型：

- 投影、排序和alpha共享固定数量的抽象弹性资源额度；
- SH、blend、控制和存储保持专用；
- 同模式连续组保持流水重叠，只有实际切换模式时才形成排空epoch；
- 动态规划给出已知工作量下的最优模式序列，作为在线策略的上界；
- 当前合成负载中动态策略均退化为单一静态配置，表明固定blend限制了alpha资源扩展收益。

R0的额度尚未映射为综合面积，不能与B0作面积公平结论。下一候选结构将研究alpha+blend配对资源或可重构blend通道。

## R1状态

`r1.py`将alpha入口、blend提交口和结果队列容量组合为配对光栅通道，并引入暂定面积额度：投影2、排序1、配对光栅2，每个模式共12额度。

- 普通合成场景分别选择均衡、光栅优先或投影优先模式，但没有帧内切换；
- 密集和强遮挡负载相对B0的模型周期减少约23%，说明R0的固定blend确是结构瓶颈；
- 人为构造的异质阶段测试会在低切换开销下选择投影优先→光栅优先，高开销时自动取消切换；
- 面积额度尚未由综合校准，上述结果只能用于架构筛选。
