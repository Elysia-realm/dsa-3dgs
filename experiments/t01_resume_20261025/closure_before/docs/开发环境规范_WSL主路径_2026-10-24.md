- 保留 Windows 智能应用控制及其他系统保护，不为本项目关闭、削弱或绕过安全策略。
- 以 WSL2 / Ubuntu-24.04 执行后续编译、仿真、综合、STA 和存储建模。Windows 继续用于
  编辑、文件管理和调用 WSL；解除原 Windows/MSYS2 拦截不再作为主线工作的前置条件。
- Windows 拦截记录作为历史环境限制保留，不将它标为“已修复”，也不反复要求用户关闭保护。

## 后续任务的执行要求

1. **先适配任务所需入口。** 检查 Windows/MSYS2 路径、`.exe`、shell、Python 和动态库依赖，
   使用 Linux 原生工具；明确版本和参数，重新编译到独立目录。不得直接将 Windows 构建缓存
   或可执行文件作为 Linux 构建结果。综合任务另行核实 Linux Yosys/ABC 与映射脚本。
2. **保持源码一致。** 权威项目目录为 `D:\3DGS`，WSL 对应 `/mnt/d/3DGS`。为编译性能复制
   到 Linux 文件系统时，保存源码清单、哈希和同步记录，明确编辑位置；不得留下两份漂移源码。
3. **迁移结果有证据。** 以同源码、同输入、同生产参数和同口径重新执行必要检查，与相匹配
   的历史证据或独立参考对照。记录工具版本、编译选项、命令、输入/源码/输出哈希、日志和差异。
   无匹配历史证据时明确说明，以独立参考和任务验收条件验证，不编造跨环境一致结果。
4. **保留历史。** 新建实验输出目录，保留旧 Windows 日志、二进制和结果的来源；不得覆盖
   旧证据或将旧结果冒称为新环境执行结果。宿主墙钟、CPU时间与RTL周期、硬件FPS分列。
5. **保持验收纪律。** 迁移不缩减必要模块/协议检查、真实五场景及T10正式范围；完成必要
   证据前不得签核。环境切换不代替生产顶层STA、存储建模、外存联动或最终PPA验收。
