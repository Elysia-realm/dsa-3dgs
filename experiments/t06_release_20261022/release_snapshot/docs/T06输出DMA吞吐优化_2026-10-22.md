# T06输出DMA吞吐优化

状态：开发/验收进行中，不代表30FPS或最终毕业设计通过。

已完成D五完整模型对拍，仍保留快照和原始配置，不复用为新RTL的签核证据。
继续暂缓Kitchen/Garden；活动五场景为Bonsai、Counter、Room、Train、Truck。

## 本轮具体瓶颈

最终RGB DMA为每个像素状态单独发一个AR单拍读取，再转码并聚合RGB写burst。
在正式分辨率下，逐像素读请求/响应状态切换和外存请求开销不能被新增算术流水隐藏，
因为RGB输出在渲染及状态写回排空后执行。故必须降低这一串行尾段开销。
这不是更改测试台后假称硬件加速，而是改变真实生产RGB DMA的读burst组织。

## 唯一有界候选

READ_BURST_BEATS参数，旧基线1，候选16。读取不跨4KiB、不跨当前80像素RGB分块；
连续接收一拍一个128bit状态，保持RGB888、行padding、epoch与背景、定点舍入完全不变。
新增读剩余拍数和异常排空状态，不增加整帧片上缓存，不改变渲染/排序数值或默认配置。
AR阻塞时地址/长度稳定；RRESP/ID错误记录；RLAST提前结束则报错结束，RLAST晚到则排空
至真正RLAST后才完成，避免未完成读事务被当成功帧。正常完成仍等待最后B响应。

## 预先冻结验证

1. 单元逐字节检查1/5/79/80/81/83宽、跨4KiB、陈旧epoch、背景合成、行padding；
   随机/周期性AR/R/AW/W/B背压、RRESP/RID/RLAST及BRESP/BID故障、错误后恢复。
2. 1920×1080输出阶段单独同条件基线/候选计时，明确这是RGB DMA阶段，不是整帧30FPS。
3. 新生产顶层五场景512条、四模式两AXI，读burst1/16同源对照80次，RGB/全序/IRQ/排空
   全部一致且真实burst发生；必要当前源默认回归、T03–T06兼容/异常检查和最终完整模型
   证据补齐后才能签核，不用局部测试替代。
4. 本轮保持mean/attribute旧模型条件不变。此前连续burst内存模型校准单独报告，
   模型变化的收益不能混进这次RTL读burst收益。

此前论文对照已记录在10-21日志。论文中on-chip image buffer和流式数据供给说明不能
只追求算术流水而忽略图像状态/输出组织；本轮不借用其1GHz或Lego FPS作为本项目达标证据。

## 已完成结果与当前断点

- 首轮单元测试后复核发现原小地址在放大分辨率后重叠；中止旧1080p尝试，保留
  units_pre_address_fix及原因。改为0x01001ff0输入、0x70000f20输出并断言不重叠后，
  41个用例重新全部通过。真实生产平台沿用已验证的独立地址区间，未受影响。
- 1920×1080输出阶段逐字节检查通过：单拍读4,616,596周期、2,073,600次AR；16拍读
  2,680,696周期、137,700次AR；读取状态数和写出字节数完全相同。周期减少约41.93%。
  若假定200MHz，输出阶段由23.08ms到13.40ms；这不是完整渲染帧的FPS。
- 五真实场景512条、四模式两AXI、读burst1/16共80/80通过，RGB与全序一致，G/P/R工作量
  不变。命令周期平均减少32.06%（ideal）、46.18%（limited）；这些子集的输出尾段占比大，
  不能把该比例直接外推至完整模型。
- 当前源80项默认RTL自检及一次综合入口通过，读burst16+dot3+alpha+4/4候选顶层lint通过。
  单元及回归日志、命令、源码哈希已保存于t06_rgb_burst_20261022。
- 同源读burst1基线的40次周期和RGB与此前D候选逐项一致，确认没有把改变测试台单拍时序
  的收益混入RTL读burst收益；候选配置10项命令/相机/错误恢复检查通过，其零opacity控制
  范围明确单列，多拍RGB错误由41项单元检查覆盖，非空真实路径由80次矩阵覆盖。
- 候选完整五模型已从冻结快照启动，状态t06_full_rgb_20261022/status.json。生产默认仍为
  单拍读；完整模型、优化配置发布集成和最终PPA/GT/30FPS缺口未闭环，T06不签核。
