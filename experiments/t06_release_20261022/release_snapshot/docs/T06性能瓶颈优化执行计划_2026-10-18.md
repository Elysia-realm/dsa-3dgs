# T06性能瓶颈优化执行计划

用户要求：优化截至T06的成果，保持截至T06的完整正确性并完成签核；项目最终至少30FPS。
本轮后续测试暂不运行Kitchen/Garden，保留旧证据。采用Bonsai/Counter/Room/Train/Truck，
相机146/120/155/150/125，至少五场景，不减少T00最终13场景和原始/1080p要求。

## 冻结范围与候选

旧五完整场景基线已保存在experiments/t06_20261018/performance_baseline，不覆盖。
当前下游排序输出回压约65%–79%，状态窗口满约50%–74%。本轮选择一个主要方向：
利用已有4-entry/4-MSHR及响应/提交旁路，减少状态读取—共享blend—有序退休之间的等待。
不复制blend算术核，不关闭共享G/P/R，不改全局有序或Gaussian-wise路径，不引入tile列表。

先执行三配置有界对照：B=2-window/2-MSHR（当前基线）；W=4-window/4-MSHR、旁路关闭；
F=4-window/4-MSHR、双旁路开启。B→W只评价现有匹配窗口/访存上下文子系统扩容，不能把收益
全部归因于单一窗口参数；W→F只评价旁路组合。暂不扩大为多深度、多网络扫描。
生产默认不在候选验证前修改。

## 开始前冻结的验收与计时

1. 新测试台准确统计command_accept至最终frame_done的周期，保留旧REAL_PERF以交叉校验，
   包含相机输入、末次RGB响应及排空。各DMA握手计数、原始日志、输入/源码/可执行配置均归档。
2. 五场景128宽、512条真实原PLY顺序子集、四模式×两AXI×三配置共120次筛选；明确为子集，
   不能称完整模型或30FPS通过。先与独立排序参考逐字节对拍，再比较同输入同条件的周期。
3. 候选若功能通过且有实质收益，扩展至同五场景完整Gaussian集合的基线/候选同条件G模式
   验证；Train/Truck需新增完整模型数据与参考。不得复用Kitchen/Garden代替新候选覆盖。
4. 所有候选必须保留T03相机/快照/continuation/错误恢复，T04 RGB DMA/IRQ/排空，T05稳定
   Bitonic和实际G/P/R共享计数，T06自主多pivot/容量/全序等必要测试；有缺项不得签核。
5. 当前功能基线跨版本单元证据只能按精确依赖复用。若生产默认或RTL改变，重建并补齐实际
   默认配置集成验证；图像数值/共享路径不能靠关闭候选或降低画质掩盖。

30FPS在200MHz对应最多约6,666,667周期/帧，且须在合同分辨率和真实存储条件下达标。
旧Bonsai基线QSU读14,062,140个128-bit描述符；当前每拍最多一读beat的独立QSU端口，
仅该流量在假定200MHz下就需至少70.31ms（上界14.22FPS），尚未计协议空拍和其他处理。
这不是芯片实测结论，但证明仅加速blend不足以解决30FPS；后续必须依据本轮数据继续处理
必要的QSU流量/服务率瓶颈，而不能只以窗口候选通过结束整个项目的性能工作。
本轮只解决具体瓶颈并量化差距，不把128宽的换算FPS当最终实时性通过。面积、STA、功耗
未测时明确保留风险；有实质退化则修复或回退。低收益停止只适用于可选扩展。
