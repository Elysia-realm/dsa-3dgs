# T06 自主分组与片外暂存接口 v1

生产顶层 `gs_accel_system_top`。默认综合 `ENABLE_AUTO_QSU=1`，默认 sequence 扩为32位。
T05 K16空间Bitonic、共享G/P/R和RGB DMA不关闭。运行时 `QSU_CONTROL.enable` 区分
新增自主命令与旧v1软件分批命令；复位为0仅用于旧驱动兼容，自主验收必须显式置1并检查计数。

## 命令与存储

| APB地址 | 字段 | 语义 |
| --- | --- | --- |
| 0x0C0 | QSU_CONTROL bit0 | 自主全输入排序开关，命令接受时快照 |
| 0x0C4/0x0C8 | SCRATCH_BASE低/高32位 | 16字节对齐；独立QSU AXI端口可寻址区 |
| 0x0CC | SCRATCH_CAPACITY | 每bank的描述符数量，必须不小于Gaussian输入总数 |
| 0x0D0 | QSU_CAPABILITIES | 0x00070801：版本1、8个子集、7个pivot |
| 0x0D4 | INPUT | 本命令进入QSU的深度可见描述符数 |
| 0x0D8 | PARTITIONS | 超容量节点实际划分次数 |
| 0x0DC | LEAVES | 向BSU完整提交的子集数 |
| 0x0E0/0x0E4 | READ/WRITE | QSU读/写描述符数量，每条16字节 |
| 0x0E8 | STALL | 叶子输出或写口阻塞拍数（重叠时只计一次） |
| 0x0EC | PEAK_STACK | 本命令DFS描述符栈峰值 |

统计为32位本命令计数（超范围自然回绕），不混入T05 BSU统计；正式冻结模型范围内须检查
未溢出。命令运行时写shadow配置不影响已接受的scratch地址、容量、相机及输入数量。
自主命令禁止continue/more-batches，整场景只发一次START；相机描述符count与APB一致。
非法容量/对齐、地址加法溢出、窄sequence或不支持的模式组合在DMA启动前以错误bit18拒绝。
CPU必须分配不与输入、相机、属性、输出重叠的scratch区域；DMA访问不得超过该区域。

bank0=`base`，bank1=`base+16*capacity`，总分配=`32*capacity`字节。每条128bit低位依次
为sequence[31:0]、GID[31:0]、signed depth[26:0]，其余清零；只存描述符，不复制Gaussian属性。
正式新增端口为 `m_axi_qsu_*`：128bit、INCR、ID0、独立读/写通道。读burst最长16拍，不能
跨4KiB；scatter写为单拍，16个有序在途槽，AW/W独立握手、B按同ID顺序退休。片外带宽和
流量必须计入性能报告，不能把这个接口看作零成本无限存储。

## 全序与容量安全

完整key `{depth符号位翻转,GID,sequence}` 作unsigned字典序比较。采集可见描述符时统计
min/max。每个节点跳过公共高位前缀，对最高不同位及其后两位生成七个对齐边界；七比较
并行分类。先计数并计算前缀offset，再稳定scatter到对侧bank的相同区间。写响应排空后
才处理子节点。按逆序压栈、正序弹出，只有整个前缀区间先于后继区间才允许向BSU提交。

重复深度继续用GID/sequence分裂，不会无限重复同一深度pivot。完全相同key时按原到达序
切为K条叶子；这是等价key顺序切分，不是将未证明有序的大桶随意切批。
默认91位key，最大栈深 `7*ceil(91/3)+1=218`，每节点存offset/count/bank/min/max；
约53,846bit（6.57KiB），不按模型N分配片上数组。后续SRAM映射和活动功耗仍由T11/T12关闭。

## 与T05流水及异常衔接

两组K条叶子缓冲负责完整性提交：只有全部有效读数据收到后，该叶子才可见于BSU。
可以读取下一叶子、输出前一叶子，并与后续QSU划分及T05各层/渲染重叠。缓冲共
`2*16*91=2912bit`，另有长度/valid/指针。T05本身双输入bank保留，不逐组重启epoch。
sequence由16扩到32后，T05主要条目存储约 `12*16*97=18624bit`，不能沿用旧位宽的面积数字。

2026-10-15发现并修复：原直接流式叶子转发在读错误发生时会将半组留在BSU，导致busy
永不排空。现在出错的未提交叶子丢弃，已经提交的完整叶子允许完成发射；读事务和B响应
排空后报错完成。QSU错误使用core错误bit1，成功RGB不会为错误帧启动。错误后新命令清空
QSU/DMA状态，不能仅清软件状态而隐藏仍在途的事务。

资源边界：七路key比较和QSU控制为专用逻辑；T05首层首对仍用共享G比较，其他CAS专用，
P/R共享不变。动态G/P/R/E控制BSU入口服务、共享PE与投影/光栅lanes，不把QSU称为全共享阵列。

## 2026-10-22 正式发布参数配置补充

正式T06配置为`verification/t06_release_profile.json`中的`t06_h_v1`，生产顶层名称不变。
通用模块默认值、QSU_CONTROL复位0仅作旧驱动兼容；正式构建必须应用该参数配置，
驱动按上文设置enable、scratch地址及capacity后一次START。验证入口为
`verification/run_t06.ps1 -EvidenceOnly`；参数导出入口为
`scripts/export_t06_release_parameters.py --tool verilator`或`--tool yosys`。

正式配置启用父scatter同步子统计：保存子节点下一轮8桶count/min/max，子节点恢复后
直接offset/scatter，根节点仍扫描count；pivot、全序、地址、叶子和APB协议不变。
除原6.57KiB描述符栈外，新增218×1712bit统计栈（1读1写generic memory）及64桶活动统计，
主要新增容量386912bit（47.23KiB）。LOCAL_RECORDS=0，不与局部子树缓存组合。
四项状态窗口/4 MSHR/双旁路、精确alpha无效事务跳过、共享dot3及最终RGB读burst16启用；
dot3新增两个P专用32×32乘法器，不冒称全部算术共享。完整参数和支持边界以配置文件为准。
以上为功能发布配置，SRAM宏/实际时序/全芯片面积功耗及T00 30FPS仍由后续任务验收。
