# RTL验证日志：流式Z预处理资源折中

日期：2026-09-15

## 1. 本轮目的与边界

上一轮已经消除属性及XYZ交接空拍，但collect阶段仍由一个共享MAC串行完成每个
Gaussian的3项相机Z乘加，n32理想AXI的collect固定为99周期。4个预处理上下文已经
能够连续向单PE发射，继续增加FIFO或上下文不会改变三MAC/Gaussian的算力下限。

本轮实现可综合的`USE_STREAMING_DEPTH_PREPASS`候选，用现有流式Z核心在collect阶段
每拍接受一个Gaussian；组内排序G和主投影XYZ仍使用原共享PE，固定主路径继续是：

`depth_group -> ordered_gaussian_issue_retire -> per_gaussian_8x8_block_walk`

候选默认关闭，不改变G/P/R/E模式、排序键、Gaussian发射/退休顺序、8x8 block遍历、
定点舍入/饱和、continuation或图像状态格式。本轮不是R接入、统一多PE阵列或PPA签核。

## 2. RTL与验证实现

- `gaussian_frame_render_pipeline`和`gs_accel_system_top`增加默认0参数
  `USE_STREAMING_DEPTH_PREPASS`。参数为0时仍使用四上下文单共享MAC预处理；为1时只把
  collect Z变换切换到`gaussian_depth_prepass_core`，共享切片继续服务G排序与主XYZ。
- `tb_real_dma_workload`及Verilator构建脚本增加同名编译开关。
- `run_shared_pe_validation.py`增加`streaming_prepass`配置，报告相对当前共享方案的周期、
  相对完整旁路的gap，并明确3个本地乘法操作仅是展开结构事实，不是面积值。
- `check_shared_pe_elaboration.py`检查候选恰有1个流式Z核心、0个共享Z适配器，同时仍有
  1个`world_to_camera_shared_mac`和1个共享PE切片。
- 新增独立审计脚本与4项Python证据测试，逐项检查frame hash、collect周期、P/G工作量、
  主XYZ工作量、默认状态和PPA声明。

## 3. 六场景真实DMA结果

Bonsai、Train、Garden、Truck、Room、Counter各取n32，覆盖G/P/R/E四种固定模式及
ideal/limited两种AXI时序。流式候选48/48相对同轮默认共享配置提速，且候选、默认共享、
完整旁路的最终frame-state SHA-256逐场景一致。

| 项目 | 默认共享预处理 | 流式Z候选 | 变化 |
|---|---:|---:|---:|
| ideal collect周期 | 99 | 66 | -33 |
| limited collect周期 | 139 | 135 | -4 |
| n32共享P grant | 384 | 288 | -96（32×3项预处理MAC） |
| 主XYZ共享MAC grant | 288 | 288 | 不变 |
| 排序G工作量/图像 | 基线 | 逐项相同 | 不变 |

整帧理想AXI固定节省33周期，平均降幅1.898638%（范围1.706308%～2.509506%）；受限AXI
固定节省4周期，平均降幅0.132402%。48项平均节省18.5周期。所有整帧节省都能由collect
缩短精确解释，没有通过减少Gaussian、commit、state读写、排序或主XYZ工作换取周期。

流式候选相对完整旁路仍平均慢1.983493%、最差慢5.423123%，所以
`performance_vs_bypass_pass=false`。候选恢复3个本地乘法器，缺少综合/STA/功耗数据，
不能据此判断性能/面积/能耗乘积更优，也不应成为默认生产配置。

## 4. 当前源码回归与结构证据

- 官方当前源码基线：前三场景96 DMA、扩展三场景72 DMA，全部图像一致；默认共享方案
  数字保持平均/最大旁路开销3.078960%/6.305578%。
- 独立流式A/B：48个候选配置全部提速；含重复参考配置的两份A/B报告共144次仿真。
- 排序候选在当前轮重新运行42配置、147,343条输出，374/374定向非压力case不退化；
  不是继承未运行的声明，也仍不是通用最优证明。
- Python 146项、Icarus 77项自检加1次综合入口通过。
- 默认、流式候选Verilator lint通过；无Error、LATCH、MULTIDRIVEN、UNOPTFLAT，仍保留
  既有非致命width/unused等告警。四份当前展开树及结构审计通过。

## 5. 审计结论与下一步

本轮证明单PE三MAC确实是理想输入下的collect算力瓶颈，也量化了其在受限带宽下几乎被
AXI等待掩盖。流式Z是有效的性能上界/消融候选，但以3个乘法器换取的整帧收益不足以在
无PPA数据时默认启用；Gate 1继续为PARTIAL，R和全共享阵列仍未完成。

下一轮不再继续堆预处理FIFO。优先实现可逐bit验证的保守Gaussian形状/block reject，
用真实`candidate_blocks/issued_blocks`和整帧周期验证是否减少R阶段无效工作；并并行梳理
无状态R算子接入共享PE的操作与上下文合同。资源能力稳定后再重标自动模式，不使用旧
0/13、12/13结果冒充当前性能。
