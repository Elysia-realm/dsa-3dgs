## 7. 最终模型构建与 checkpoint 闭环

### 7.1 构建环境兼容处理

真正进入链接后，MSYS2 UCRT64 GCC 16.2.0-3 暴露出其新 C++11 ABI 的
`std::string` C4 constructor 符号无法由同版本 `libstdc++` 解析的问题。最小 C++
探针可独立复现，而 `_GLIBCXX_USE_CXX11_ABI=0` 探针可正常链接。因此构建脚本仅对
Verilator 运行时和其自动生成的仿真 harness 统一使用兼容 ABI，并通过 `MAKEFLAGS=-B`
确保所有 C++ 对象按同一 ABI 重编译；该设置不触碰 RTL 数值或微架构。

### 11.2 实际流水事件与建议器

- 从真实数据通路导出 group pressure、sort busy、projection busy、raster busy、
  block candidate 和 terminated skip 事件；
- `gaussian_mode_advisor` 仅在逻辑帧计算期间采样，空闲期暂停观察窗口和驻留计数，

- 顶层只接受一个未决推荐，避免较新的窗口结果覆盖尚未安全提交的推荐。

### 11.3 APB 与安全切换语义

新增 `0x044 AUTO_MODE`：bit 0 控制自动模式，bit 1/3:2 返回推荐或队列状态，
bit 5:4 返回最近窗口胜者，bit 6 返回建议器未决状态，bit 7 返回 commit/mode pending。

自动推荐复用已有 runtime mode shadow/commit 数据通路，只在下一次新帧建立 epoch 的安全
边界提交；continuation 不建立新 epoch，因而不会在同一逻辑帧中途切换。关闭自动模式
时，软件 shadow 配置重新取得控制权。另增加断言：`active_mode_o` 发生变化时必须同时存在
`mode_commit_done`，防止未来改动绕过安全提交路径。

### 11.4 定向验证与结论边界

系统级 APB 定向测试从 E 模式启动真实 Gaussian 观察帧，确认首个推荐进入单未决队列，

推荐为 P，而最近窗口胜者随后可为 R；这验证了单未决语义，不能解释为 P 对真实负载最优。

## 14. 13 场景固定/自动模式真实标定矩阵（2026-09-11，功能 PASS；策略性能 NOT PASS）

### 14.1 标定工具与公平比较口径

新增 `scripts/run_real_mode_calibration_matrix.py`。它对每个真实工作负载依次执行固定
G/P/R/E 四种模式及 E→自动选择双帧探针，并强制检查：

- 四个固定模式的完整 framebuffer 文件逐字节相同；
- 自动模式内部观察帧与选择帧 RGB/T 逐像素相同；
- 固定运行实际 active mode 与请求模式一致；
- 所有运行包含结构化性能记录和 RTL PASS 标志。

`run_real_auto_mode_probe.py` 同时扩展为自动识别两种属性布局：完整批次的
`attribute_sparse.memh + global_gid.memh`，以及 32-Gaussian 跨场景负载的帧内连续
`attribute.memh`。两类输入共用相同 RTL 主路径。

策略准确率采用公平口径：将“自动所选模式的独立冷启动固定运行周期”与四模式 oracle
最小周期比较。自动第二帧自身的周期仍保留为 integration 数据，但因其包含 epoch 切换、
APB 测试序列及上一 epoch 外存状态，不能直接作为模式本体的 oracle 周期。

### 14.2 13 个真实场景结果

覆盖 bicycle、bonsai、counter、drjohnson、flowers、garden、kitchen、playroom、room、
stump、train、treehill、truck，共 13 个不同相机视角索引；每个负载为 32 Gaussian、
64×43 输出。

固定模式平均周期：

| 模式 | 13 场景平均 cycles |
|---|---:|
| G | 1,628.231 |
| P | 1,634.231 |
| R | 1,634.154 |
| E | 1,663.462 |

13/13 场景的固定模式 oracle 均为 G。当前自动策略结果为：

- 12 个场景产生有效 R 推荐；1 个 garden 负载只有 4 个完整观察窗口，未达到默认滞回/
  最短驻留条件，因而保持初始 E；
- 精确命中 oracle：0/13；
- 距 oracle 不超过 1%：12/13；
- 平均 oracle gap：0.573828%；最大 gap：3.147700%（无推荐的 garden）；
- 13 个场景四模式 framebuffer 全部逐字节一致；
- 13 个场景自动双帧 RGB/T 差异全部为 0。

多数 R 推荐来自短负载在第 4 个可判定窗口附近已进入投影/光栅阶段；固定性能却显示这些
负载中 G 比 P/R 仅快约 5–6 cycles。这说明目前 P/R 的额外 lane mask 没有形成足够显著的
可利用吞吐收益，而 group 服务率削减会稳定付出代价。单纯把首未决改为末窗口、多数投票
或把 R 阈值调高，只会拟合当前 32-Gaussian 样本，缺少物理资源收益依据。

结合上一节 1,024-Gaussian Bonsai batch 0：自动选择 G，而独立固定 oracle 为 P；差距为
977 cycles，即 0.198639%。因此当前控制器在 14 个已有真实标定点上均未精确命中 oracle，
但除短到无法形成推荐的 garden 外，其余 13 个点都在 1% 以内。结论应表述为“近似稳定、
尚未完成收益驱动校准”，不能表述为自动模式已经最优。
