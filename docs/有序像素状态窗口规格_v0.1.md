# 有序像素状态窗口规格 v0.1

## 1. 目标与非目标

目标是在不改变 Gaussian 顺序的前提下，允许两个不同像素的 read–blend–commit 事务部分重叠，缓解当前单事务 state path 对 4-lane 投影/SH/光栅前端的反压。

本设计不改变“深度分组 + Gaussian 有序发射 + Gaussian 内部 8×8 block 遍历”，不增加 per-tile bin/list/sort，不允许像素提交越过更老事务，也不通过降低数值精度换取吞吐。

## 2. 证据与收益边界

13 场景 n32 探针中：

- ideal 总计 63858 cycles，`window_wait` 50905（79.7%）；limited 总计 119287 cycles，`window_wait` 104879（87.9%）。
- 两种 profile 的 `window_same=0`，全部等待样本的队首下一事务都是不同 `{epoch,pixel}` key，说明 2-entry window 有可利用候选。
- 总计 8651 commits、6734 misses，miss/commit=77.8%。因此只添加 FIFO 不会提高 cache/AXI 服务率；大量候选仍会在单 MSHR 上串行。
- 假设所有等待都可完美二路重叠，Amdahl 乐观上限约为 ideal 1.663×、limited 1.784×。这是不可直接达到的上界，不是预计加速比。
- 按总体 cache-hit 比例粗略折算，单 MSHR hit-under-miss 的参考上限只有约 1.10×；准确收益必须由 RTL 实测决定。

完整数据见 `experiments/rtl_workloads/all13_n32_state_window_probe_2026-08-13.json` 及其 Markdown 汇总。

## 3. 事务与顺序合同

每个窗口项至少保存：

- 单调递增 sequence；
- 完整 `{epoch_id,pixel_id}` key；
- alpha 结果携带的完整 metadata、RGB、alpha/pass；
- query 状态、state response、blend 状态和最终 RGBA/T；
- miss/error 标记。

必须满足：

1. 输入已经由 alpha ordered-retire 排序，窗口按接受顺序分配 slot，禁止后到事务占用更老 sequence。
2. 只有 head slot 可以对外 commit 和更新 architected pixel state；tail 即使先完成也必须等待。
3. tail 的完整 key 与任一未退休旧项相同，则不得发起独立 state query；必须等待旧项 commit 后重新读取，或由经过逐位验证的精确前递获得旧项的新状态。
4. 对外 commit 出现背压时，head 的 metadata、pixel、epoch、结果和 terminated 标记必须保持稳定。
5. error 随原事务保留并按序退休；不能因 younger 成功而覆盖 older error。
6. 帧完成必须等待窗口为空、cache/MSHR 为空、AXI read 响应和 AXI write B 响应全部回收。

## 4. 分阶段微架构

### Phase A：2-entry ordered window + 单 MSHR hit-under-miss

- 两个窗口项使用完整 key 比较器形成最小 hazard CAM。
- cache 在一个 miss 等待期间允许查询不同 key；hit 可返回并提前完成 blend，miss 则保留到唯一 MSHR 可用。
- response 必须携带 slot tag，或由不会歧义的内部路由状态绑定到 slot；禁止依赖响应到达时间猜测归属。
- 共享一个 `blend_fixed_core`。其一拍流水吞吐足够，输入仲裁优先 older ready slot；结果按 slot tag 写回窗口。
- head commit 时执行 state update。tail 若与 head 同 key，不能使用 commit 前读出的旧状态。
- direct-mapped cache 的同 index、不同 tag 不是 RAW，但必须验证 fill/update 同周期的覆盖优先级与 tag/data 原子性。

Phase A 不增加第二个 AXI miss，只对 cache hit 隐藏既有 miss 延迟，面积成本主要是第二份事务寄存器、两个完整 key 比较器、slot 状态和 response tag。

### Phase B：可选第二 MSHR

仅当 Phase A 在 13 场景及更大完整 trace 上收益不足、且综合 PPA 允许时启用：

- 两个 MSHR 各保存完整 key、cache index、epoch、slot tag、error 和 AXI ID。
- AXI `ARID/RID` 必须唯一映射 MSHR；允许响应乱序，但 fill 和 slot response 必须回到正确事务。
- 同 key 合并或阻塞；同 index 不同 key 可并行读取，但 cache fill winner 只能影响命中率，不能影响各 slot 得到的数据。
- reset/soft reset/frame end 不得遗失已发出的 AXI 响应；若协议不支持取消，必须排空后再宣告 idle。

## 5. 动态可重构结合方式

窗口/MSHR 数量是硬件上限，不在帧中改变。epoch 安全边界可配置：

- G/P/R 模式：若 state path 是瓶颈，可启用 2-entry window；
- E 模式最初评估过仅启用 1 项，但 train n32 的 ideal/limited 周期分别退化到 6979/11409，相对二项窗口损失过大；在目标工艺功耗证据出现前，四模式均保留 2 项；
- mode commit 只能在窗口、cache、MSHR 和 AXI state path 全部 idle 的 epoch boundary 生效。

这使 GCC 式数据流和动态可重构在同一瓶颈上协同：上游 lane 数与 state-window 深度必须一起由阶段计数器决策，而不是始终开启全部并行资源。

## 6. 必需验证

- 定向：不同 pixel hit-under-miss、相同 pixel RAW、相同 index 不同 tag、younger 先完成、commit 背压、AXI 响应乱序、error、reset/frame drain。
- 随机：带完整软件 scoreboard 的至少 1000 笔事务，随机 key 重复、cache 冲突、query/response/commit 背压。
- 形式/SVA：分配顺序、head-only commit、同 key 不并行 query、stall 稳定、accepted=committed+occupancy、slot tag 唯一。
- 系统：13 场景 ideal/limited frame-state 逐位等价，G/P/R/E 均验证 active mode 与 epoch，完整回归和 Verilator lint 无组合环/多驱动。
- PPA：Phase A/Phase B 分别综合；报告 CAM、窗口寄存器、MSHR、AXI ID logic 的面积和功耗增量，不把 SRAM 宏遗漏在总面积之外。

## 7. Go/No-Go 门槛

- Phase A 必须保持所有逐位正确性测试，并在 13 场景几何平均至少获得可重复的端到端周期改善；若不足 3%，默认关闭或回退。
- Phase B 只有在相对 Phase A 再获得显著收益且 timing/面积/功耗可接受时保留；具体 PPA 门槛在目标工艺库到位后冻结。
- 任一方案若引入 per-tile 结构、打破 Gaussian/pixel 顺序或无法证明同像素 RAW，立即 No-Go。
