# T08 原生 AXI 窗口、状态行缓冲及共享 LPDDR4

## 生产地址重放结果

## 16 行状态缓冲的功能与吞吐取舍

在独立 RTL 中实现 16 条直接映射的 64 字节缓存行，数据载荷共 1024 字节，另计标签、有效位、脏位和控制。命中操作针对一个 16 字节扇区；缺失时整行取回，替换或刷新时整行写回。只有收到成功响应才释放脏行。定向测试覆盖部分字节写、同址重读、标签冲突、保留未写扇区、填充失败、脏行写回失败、刷新失败后重试、地址对齐及输出背压。

用十个窗口的真实有序地址加确定性的测试写数据驱动 RTL。独立软件记分板检查每个读值、响应及刷新后的全部后备数据；每个实际 64 字节请求与独立替换模型逐条匹配。每窗冷启动并计入最终脏行排空。在饱和离线重放中，16 行方案使请求数减少 61.50%–74.89%，折算的原 AXI 有效字节服务率为 9.82–14.71 GB/s。1 行模型在十个窗口均增加请求，说明只聚合最近一个地址会受冲突影响。证据为 `state_lines_20261123/report.json`。

随后将同一 RTL 请求端接入实时 Ramulator 回调。按原始 AXI 相对周期给出请求，假定请求端 200 MHz、DRAM 1200 MHz，读等待真实模型返回，写在控制器接受时应答，最后统计模型尾部排空。接受地址和写值仍逐项核验，输出行请求与离线序列完全相同。十个窗口实际需要原 8192 周期的 2.15–6.09 倍，含排空的有效吞吐只有 0.36–0.59 GB/s。主因是串行原型每次仅服务一个操作，未重叠行填充、替换和后续命中。决定保留行合并的流量证据，回退该串行接口，不接入生产配置。若开发并发版本，须先验证同址最新值、按序响应、脏行排空及多项挂起时的错误恢复。见 `state_lines_timed_20261123/report.json`。此前编译缺少固定宽度整数头文件的日志已保留，补齐后全部十例通过。

## 共享 DDR 返回时序接入

为建立同口径对照，先在 WSL 原生 Verilator 生产顶层测试台接入无行缓冲的七端口时序桥。真实地址和数据继续由生产端口传输，测试台原有存储保存功能数据。一次突发触及的每一行进入共享轮询仲裁，每 DRAM 周期最多提交一行；读等全部行的模型回调后才允许原 AXI 从端发出首拍。写地址与 WLAST 独立配对，控制器接收整笔写后才允许返回 B。运行结束另计模型队列尾部排空。该实验采用指定的通道、频率、行大小及写应答策略，实体板级校准仍开放。

预定先以五场各 512 条真实记录做功能与时序桥冒烟，分别运行 Q24 原始/紧凑、理想/共享四种组合。通过后，以相同五场全部 Gaussian、宽 128、Q24 原始及紧凑运行共享 LPDDR4 整帧，对照冻结的理想接口图像、排序和终止状态。统计实际 AXI 突发、行提交、R/B 响应、命令到最终完成周期和尾部排空。入口为 `scripts/run_t08_shared_ddr.py`。进度及错误记录以 `shared_ddr_render_20261123/status.json` 与原始日志为准。T08 未签核，原生 30 FPS、正式逐视角 GT 及集成 PPA 仍未关闭。
