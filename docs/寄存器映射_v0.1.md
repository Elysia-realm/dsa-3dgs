# 3DGS ASIC控制寄存器映射 v0.1

2026-10-13 T05 v2：`0x084` bit4表示空间流水Bitonic，bit[31:16]为K，生产K16为
`0x00100019`。bit4=1时，`0x09C`改记多排序层同拍前进次数，`0x0A0`改记收/发同拍握手
次数；bit4=0保留旧fallback/phase_grants含义。G共享比较计数为每子集首层首对请求，不能
再按每折叠批解释；专用比较及总阶段数仍在`0x08C/0x094`。完整语义见T05 v2规格。

`ERROR_STATUS` bit[9:0]为计算帧错误；bit10/11为mean DMA协议/配置错误；bit12/13为属性DMA协议/配置错误；bit14/15为像素写回DMA响应/配置错误；bit19为camera DMA协议错误，bit20为camera描述符/命令配置错误，bit21为continuation相机不一致；bit22/23/24分别为最终 RGB DMA 配置、读响应/协议、写响应错误。bit8同时用于记录busy期间重复START。

`CONTROL.clear`同时清除done sticky、error status和两个IRQ pending位。IRQ pending与enable分离：事件在中断被屏蔽时仍会记录，软件可轮询后清除。正常帧设置done pending；错误帧同时设置done与error pending。

未知地址产生`PSLVERR`。手动模式下，MODE写入shadow；帧内commit请求只锁存，下一帧
启动时与新epoch原子成为active。自动模式下，真实流水事件进入长窗口建议器，首个满足
裕量、滞回和驻留条件的建议进入单未决队列，并同样只在下一新帧epoch边界提交。
continuation批次不得改变epoch或应用排队建议。关闭自动模式会清除建议器窗口/请求，并用
软件shadow模式覆盖尚未提交的自动推荐。

`0x048–0x060` 是同一时钟沿更新的只读窗口快照。由于 APB 以多个事务读取，软件应先读
`ADVISOR_WINDOW_INDEX`，读取六项计数后再次读取 index；若两次不同，则跨越了窗口更新，
应重读。这样不需要冻结实时建议器，也能获得一致的诊断样本。计数只包含
`core_frame_busy` 期间的周期，空闲时间不进入窗口。

`0x064–0x07C`是当前逻辑帧实时饱和计数器：新帧清零，continuation保留。
这些计数只覆盖共享PE。可选`USE_PARALLEL_GROUP_SORT=1`候选每批一对走共享G，其余对由
本地比较器执行；本地工作不进入G grant或utilization，不能用G grant下降推断总比较减少。
G代表稳定排序比较，P代表相机Z深度预处理MAC及主投影XYZ MAC，T05生产R代表old_T×alpha共享MAC；这些计数不属于上方
advisor原子窗口快照。
START 接受时会原子快照 Gaussian/camera/attribute/output 基址、count、尺寸、模式和
continuation 控制。生产默认先从 CAMERA_BASE 读取 224 Byte v1 描述符，校验完成后才启动
mean DMA 与帧核心；格式和恢复规则见 `docs/命令与相机描述符规格_v1.md`。
默认主投影共享时，P grant应为`3×输入mean数 + 9×实际发射的完整Gaussian数`；被深度预处理
剔除的Gaussian不进入第二项。关闭`USE_SHARED_PROJECTION_PE`时第二项为0。
## 2026-08-09 扩展说明

T05（2026-10-10）新增当前含义：`0x084` bit3标识Bitonic，bit[31:16]为K，bit0标识
计数可用；生产K8为`0x00080009`。`0x088–0x098`为shared/local CAS、swap、stage、
退休非空子集数，`0x0A4`为共享比较等待拍，其余历史Odd-Even专有计数为0。
真实R grant不再要求为0；G/P/R权重与共享/专用边界见T05规格。

以下2026-08-09条目为历史，保留位和OUTPUT_BASE当前语义以本文件前部及RGB v1为准。

- `ERROR_STATUS` 现为完整 32 位只读寄存器；原 bit0–15 定义保持兼容。
- bit16：image-state backing AXI 读响应或协议错误（RRESP/RID/RLAST）。
- bit17：image-state backing AXI 读配置或 16 Byte 对齐错误。
- bit31:18：保留，读零。
- `OUTPUT_BASE` 同时作为像素状态 write-through 写回和 cache miss 读回的 backing store 基址，每像素记录固定 16 Byte。
