# RTL验证日志：动态可重构Lane操作数隔离

日期：2026-08-14

## 1. 问题

G/P/R/E模式已真实控制projection、SH和raster/alpha的valid发射，但三个lane
调度器此前仍把每个变化的输入packet广播到全部物理lane。即使未选中lane的
`valid=0`，其组合算术输入仍可能随广播数据翻转，削弱动态可重构的节能价值。

## 2. 修改

- `ordered_projection_lane_scheduler`：只给dispatch选中的projection lane传数据；
- `ordered_sh_lane_scheduler`：同时覆盖SH阵列和alpha阵列，只给选中lane传数据；
- 兼容的`projection_lane_scheduler`同步采用相同合同；
- 其他lane输入保持全0，valid/ready、轮询顺序和ordered retire均不变；
- 配置与相机常量仍广播，后续ASIC ICG可进一步门控时钟和常量路径。

该实现属于组合operand isolation，不等同于完整ICG，也不改变运行时物理lane数。

## 3. 验证

- scheduler定向TB新增检查：选中lane收到原packet，其余lane严格为0；
- `ENABLE_OPERAND_ISOLATION`默认关闭，研究配置显式开启；参数已从
  `gs_accel_system_top`贯通到projection、SH和raster/alpha三个真实阵列；
- Icarus完整RTL回归PASS；日志保存为
  `tmp/operand_iso_iverilog_2026-08-14.log`；
- bundled Python 89项合同测试PASS；日志保存为
  `tmp/operand_iso_python_2026-08-14.log`；
- Verilator 5.050默认2+2 lint PASS；4+4、双旁路、operand isolation开启的
  参数化lint同样PASS；两者的UNOPTFLAT/MULTIDRIVEN/LATCH/Error均为0；
- 参数化lint日志分别为`tmp/operand_iso_verilator_default_2026-08-14.log`和
  `tmp/operand_iso_verilator_4x4_2026-08-14.log`；
- train n128/8x4开启双旁路后周期仍为ideal 3394、limited 6685，commit/miss/
  read/write和frame-state哈希不变。

脚本开关与功耗代理JSON已闭环：
`experiments/rtl_workloads/operand_isolation_switch_smoke_2026-08-14.json`包含6个
真实训练属性配置，顶层与逐项`enabled`均为true；每项均满足
`broadcast=4*isolated`及`avoided=broadcast-isolated`。

## 4. 功耗代理指标

在4个物理lane下，每项输入以前暴露给4个lane，现在只暴露给1个lane。
train n128/8x4的projection/SH/alpha issue分别为128/128/1421，共1677项：

- 广播结构的lane-wide packet暴露：6708次；
- 隔离后的非零packet暴露：1677次；
- 避免5031次，即75%。

这是字级数据暴露代理，不是bit-toggle、SAIF或功耗报告。实际节能取决于综合
映射、门控单元、布线电容和时钟树；目标工艺可用后需以隔离开/关网表及真实
活动文件比较动态功耗。面积代价主要是每lane的数据门控/选择逻辑，目前不
虚构门级面积。

## 5. 决策

操作数隔离不增加所选lane主数据路径的逻辑级数，功能与周期均未变化，并直接
补强动态可重构的低功耗语义，因此保留。ASIC阶段仍需插入ICG，特别是E模式
下关闭未使用lane寄存器和时钟树；本文不能声称已经完成物理时钟门控。

该局部优化至此收敛。在具体工艺综合、STA和活动文件可用前，不再继续增加
宽数据门控层级；下一主阶段转入完整帧分组执行、RTL帧输出与PSNR/SSIM/LPIPS
闭环。
