# 3DGS 动态可重构硬件加速系统规格 v0.2

- 状态：B0周期/流量模型首版完成，待真实场景与RTL校准
- 日期：2026-08-03
- 继承：`系统规格_v0.1.md`全部研究问题、范围边界、接口、正确性不变量与验收原则
- 保密要求：仅存放于本地工作区，不上传网络或公开平台

## 1. 本版冻结内容

本版将v0.1中的固定功能基线B0落实为可执行周期模型，并冻结以下第一版架构语义：

1. 深度阶段先计算视空间深度并执行near/far剔除，再进入硬件式递归多枢轴分组。
2. 深度分组只要求组间全序，组内由Bitonic网络进行稳定精排；相同深度用Gaussian ID作为次关键字。
3. 投影、组内排序、SH和光栅阶段允许组间流水重叠。
4. alpha结果进入有限队列；不同像素块允许乱序选择混合，同一块必须等待前驱任务完成。
5. 提前终止维持逐像素T状态；只有块中所有像素均终止，才能不再生成该块的后续任务。
6. 当前B0资源数量固定，不执行运行时重配置；R0将在相同任务图和资源预算上扩展。

## 2. 深度分组规格

### 2.1 输入与键

- 输入记录：`(depth, gid, payload)`。
- 全序键：`(depth, gid)`，按从近到远排列。
- 默认最大组大小由`RenderConfig.group_size`指定；默认枢轴样本数为7。

### 2.2 递归多枢轴分组

1. 从当前输入到达序列中等间隔抽取少量确定性样本。
2. 只对枢轴样本执行小规模排序。
3. 用所有枢轴对记录分桶；超出容量的桶递归处理。
4. 按桶序输出组，保证前组最大键不大于后组最小键。

模型报告输入数、输出组数、递归深度、分区轮次、比较次数上界和组大小。该算法用于验证RCA式前端的可行性，不意味着最终RTL必须使用相同枢轴选择策略。

## 3. B0流水时间模型

### 3.1 延迟与吞吐

- `latency`表示单项输入发射到结果就绪的流水延迟。
- `throughput`表示每周期可接收的输入数，并决定后一组能够开始占用该单元的时间。
- 因此投影、排序和SH的“下一组可发射时间”按busy/issue周期推进，而“当前组结果完成时间”包含latency。
- 这种写法表达充分流水化单元；若后续RTL不能达到该启动间隔，应以综合结果回填配置。

### 3.2 组内排序

- 当前比较次数按输入补齐到2的幂后的Bitonic网络估计。
- busy周期约为比较次数除以并行比较器数向上取整，再叠加网络流水延迟。
- 尚未计入跨级布线、缓冲转置和非满组门控的具体成本。

### 3.3 光栅任务顺序

- 工作生成顺序为全局`(gaussian_order, task_id)`，确保alpha发射不越过深度序。
- 每个块记录最近任务作为后继任务的`predecessor`。
- 混合器可从结果队列中选择任意依赖已满足的块，从而利用块间并行隐藏同块依赖。

## 4. Scoreboard与有限队列

### 4.1 状态

- alpha阵列数、blend阵列数、各自流水延迟。
- 结果队列深度，包括alpha在途结果和等待混合的结果。
- 每块最近未完成任务的前驱关系。

### 4.2 停顿定义

- `scoreboard_stall_cycles`：结果队列中存在任务，但所有候选任务都在等待同块前驱。
- `result_queue_stall_cycles`：alpha输入已经就绪，但在途和待混合结果达到队列容量。
- `input_wait_cycles`：alpha流水无现成任务，等待上游SH结果。
- `scoreboard_overhead_cycles`：启用块依赖与禁用依赖两次模拟的完成周期差。

### 4.3 第一轮观察

- 稀疏、块间不重叠负载：scoreboard停顿和依赖额外周期均为0。
- 多块密集覆盖负载：不同块交错可隐藏依赖，主要瓶颈转为混合吞吐和队列背压。
- 单块热点负载：503个scoreboard停顿周期，依赖使光栅结束时间增加441周期，是需要重点防御的退化访问模式。

以上仅是合成验证，不可外推为真实场景分布。

## 5. 提前终止与工作生成

当前周期模型用精确FP32 alpha/T轨迹生成任务：

1. 对包围盒触达的每个块计入`candidate_blocks`。
2. 若块内所有像素此前已经终止，计入`skipped_terminated_blocks`且不生成任务。
3. 否则生成任务并按活跃像素更新T；单个像素终止不允许跳过同块其他像素。

该方式提供功能正确的工作量轨迹，但暂未模拟“终止状态从混合级反馈到任务生成级”的实际往返延迟和缓冲需求。R0/RTL模型必须显式加入这部分控制时序。

在96×96强遮挡合成负载中，启用提前终止相对近似禁用配置：候选块跳过46.3%，发射任务减少43.3%，模型周期减少42.3%，SRAM逻辑流量减少53.1%。这些数值只验证算法收益路径，不能作为论文中的真实场景结论。

## 6. 流量模型

### 6.1 DRAM

- 深度属性：每高斯3个FP16坐标。
- 几何属性：通过深度剔除后读取mean、scale、quaternion和opacity。
- SH属性：只为投影后仍在屏幕内的高斯读取，默认48个FP16系数。
- 输出：每像素3个FP16颜色分量。

### 6.2 SRAM

- 深度/ID排序记录的读写。
- 每个光栅任务的投影特征读取。
- 活跃像素RGB/T状态的读改写。

当前尚未计入bank冲突、端口复制、缓存行填充、burst效率、地址/队列元数据及终止反馈流量，因此是逻辑字节数而非物理总线事务数。

## 7. 验证状态

截至本版，共21项自动化测试通过：

- FP32黄金模型7项：投影、遮挡、稳定排序、剔除、低opacity、逐像素终止和旋转各向异性。
- 分组4项：随机性质、等深度、单调对抗输入和容量/全序不变量。
- scoreboard 4项：重叠依赖、无冲突、小队列背压和队列深度敏感性。
- B0 6项：确定性、流量、延迟属性读取、全局排序、提前终止收益、稀疏/热点访问行为。

原始合成扫描结果保存在`experiments/b0_workload_sweep.json`。

## 8. 当前局限与使用规则

1. 所有周期来自可配置架构假设，尚未由RTL综合校准。
2. 当前输出FPS只等于假设频率除以模型周期，不得称为实测性能或硬件预测精度结论。
3. 合成场景用于定向验证机制，不代表Synthetic-NeRF、Tanks & Temples或Deep Blending的统计特征。
4. 当前alpha任务全局按高斯顺序发射；后续可研究在不破坏每块依赖的前提下更积极的跨高斯发射。
5. 当前模型未计算面积、功耗和重配置开销，不能用于证明R0优于B0。
