# 完整帧深度分组批次执行合同 v0.1

日期：2026-08-14

## 1. 目的

13个训练场景合计约3978万Gaussian，不能把完整场景一次性装入当前有限容量的
`depth_group_buffer`和`stable_group_sorter`。完整帧执行必须扩展为连续批次，同时
保持既定GCC式主路径：

1. 深度分组；
2. Gaussian按前到后顺序发射；
3. 每个Gaussian内部遍历8x8 block；
4. 像素状态按原顺序blend和head-only commit。

本合同不建立per-tile bin、tile list或tile sort。

## 2. 批次不变量

- 第一批创建新render epoch并初始化逻辑帧；
- continuation批次必须保持相同epoch、输出基地址、图像尺寸和相机配置；
- 前一批的全部projection/SH/raster/blend/AXI写事务排空后，下一批才能进入；
- 像素RGB/T、termination状态及外部frame state跨批次保留；
- 批次之间的Gaussian顺序必须与全局`(quantized depth, global GID)`顺序一致；
- 当前v0.1在同一逻辑帧的批次间冻结G/P/R/E模式；模式仍可在逻辑帧边界
  动态切换。后续若支持帧内批间切换，必须把资源配置版本与render epoch解耦，
  并证明不会清除像素状态；
- 最后一批排空后才产生逻辑帧done和最终质量评价图像。

## 3. 容量规则

当前硬件有4个coarse depth group，每组容量为`GROUP_CAPACITY`，sorter容量为
`SORT_CAPACITY`。在尚未实现并验证pivot builder前采用保守规则：

```text
batch_gaussians <= min(GROUP_CAPACITY, SORT_CAPACITY)
```

这允许一个批次全部落入同一个coarse group而仍不溢出。只有离线或硬件pivot
builder证明四组各自不超过容量后，才允许把上界提高到
`4 * min(GROUP_CAPACITY, SORT_CAPACITY)`。不能只按平均四等分假设容量安全。

## 4. 本地规划器

`scripts/plan_full_frame_execution.py`逐批读取本地PLY，不上传数据，并报告：

- 深度有效和定点可表示的Gaussian数量；
- 全局GID位宽；
- mean stream、dense attribute store和pixel state容量；
- group容量8/64/256下的保守与有证明条件的批次数；
- SH定点饱和值数量；
- 仅作诊断的屏幕中心候选数量。

屏幕中心候选绝不能作为完整帧剔除条件，因为中心在屏幕外的大Gaussian仍可能
覆盖图像。真正的screen/bbox cull继续由projection路径完成。

示例：

```powershell
python scripts/plan_full_frame_execution.py --scene bonsai `
  --max-dimension 64 --group-capacity 8 --group-capacity 64 `
  --group-capacity 256 --output experiments/full_frame_bonsai_plan.json
```

## 5. 后续RTL接口

v0.1已经加入显式的fresh-frame/continuation命令语义，而不是把每批伪装成新帧：

- `CONTROL[0] start`：保持原有命令兼容；
- `CONTROL[3] continue`：该start属于已打开逻辑帧的后续批；
- `CONTROL[4] more_batches`：本批完成后逻辑帧仍保持打开；
- `STATUS[6] frame_open`：至少还有一个continuation批次待提交；
- `ERROR_STATUS[18]`：fresh/continuation序列非法。

continuation不增加epoch，不清除pixel/termination状态，也不重新应用待切换模式；
中间批排空AXI和内部状态但不产生逻辑frame done/IRQ，末批才产生。RTL定向测试
已经证明第二批保持同一epoch并在第一批像素状态上继续blend；system/APB测试
覆盖了中间批无done、末批done以及孤立continuation报错。

硬件会锁存首批的输出基地址和图像宽高；continuation若改变其中任一项，同样按
非法序列置bit18并拒绝发射。相机投影常量现由 `CAMERA_BASE` 指向的 v1 描述符经
AXI DMA 装载。fresh batch 锁存完整相机不变量；continuation 重新读取描述符并逐字段
比较 R/T、相机位置、内参、near/far 和 regularizer，pivot 与 count 可随批改变。
逐字段不一致会拒绝启动并置错误位21。

仍未完成的是：把全场景PLY真正生成容量安全、全局有序的连续DMA批次，并以
跨批frame-state哈希对拍位精确定点参考。

## 6. 评价边界

容量计划不是完整帧渲染结果，不能用于PSNR、SSIM、LPIPS、FPS或ASIC PPA结论。
正式画质报告必须来自相同完整Gaussian集合的RTL/位精确定点输出，并分别与可信
FP32参考渲染和（若有）数据集GT配对。LPIPS仅使用本地离线依赖与权重。
