# T03 命令与相机 DMA 签核日志

日期：2026-10-05  
任务：T03 — 命令与相机输入闭环  
结论：完成并签核；下一项为 T04。

## 1. 本次关闭的验收项

- 定义并冻结 camera descriptor v1：固定 224 Byte，tag/version 为 `0x47534301`。
- 新增 AXI4 相机描述符读取 DMA，支持 4 KiB 边界分裂，并校验 AXI ID、RRESP、RLAST、
  地址对齐、tag、尺寸、near/far 和 pivot 次序。
- 生产顶层默认启用相机 DMA。START 接受时锁存 Gaussian、camera、attribute、output 基址、
  数量、尺寸、模式和 continuation 控制；相机 DMA 延后一拍从锁存的 `camera_base` 启动。
- 相机描述符完成并通过校验后才允许 mean DMA 和计算核心启动。描述符 count/尺寸必须与
  命令快照相同。
- fresh batch 锁存相机身份；continuation 逐字段比较 R、T、相机位置、内参、near/far 和
  regularizer。count 与 pivot 可按批次更新，相机不变量变化会拒绝该批次且不增加 epoch。
- 增加相机 AXI/协议错误、描述符/命令错误和 continuation 相机错误状态；支持
  `STATUS_CLEAR` 修正后重试及 `SOFT_RESET` 恢复。
- workload 生成器输出带版本 tag 的描述符；新增主机侧工具，生成 224 Byte 小端二进制和
  有序 APB 写事务示例。

协议与寄存器说明见 `docs/命令与相机描述符规格_v1.md`、
`docs/寄存器映射_v0.1.md` 和 `docs/APB帧命令状态与中断规格_v0.1.md`。

## 2. 主要实现

- `rtl/dma/axi4_camera_config_read_dma.sv`：版本化描述符 AXI reader。
- `rtl/gs_accel_system_top.sv`：命令状态机、原子快照、相机装载、continuation 比较和错误闭环。
- `model/io/dma_workload.py`、`scripts/build_full_frame_rtl_batch.py`、
  `scripts/build_full_frame_rtl_batch_stdlib.cpp`：生成 v1 tag。
- `scripts/build_t03_command.py`：主机命令与二进制描述符示例。
- `verification/rtl/tb_axi4_camera_config_read_dma.sv`：DMA 单元验证。
- `verification/rtl/tb_gs_accel_system_camera_dma.sv`：命令、装载、错误和 continuation 集成验证。
- `verification/rtl/tb_real_dma_workload.sv`：生产默认相机 DMA 下的非空 Gaussian 真实负载验证。

## 4. 停止决定与剩余边界

T03 的必要输入闭环已经完成。依据清单的停止条件，本轮不继续增加多版本描述符兼容、
多级命令队列或操作系统驱动框架，这些扩展不会关闭当前新增验收项。

以下内容仍明确保留给后续任务：

- T04：最终 RGB 帧格式、背景合成、量化和 burst 输出 DMA；
- T05/T06：Bitonic BSU 与多 pivot QSU 的正式分层排序和全场景自主调度；
- T10：正式场景、视角和 GT 画质验收；
- T01/T11/T12：STA 环境、存储建模和最终双工艺 PPA。

必须用新版生成器重建，硬件不会静默接受旧格式。T01 断点保持，不因 T03 签核改变状态。
