# 动态投影前端规格 v0.3

- 日期：2026-08-04
- 平台：工艺无关SystemVerilog，目标ASIC
- 保密边界：代码、模型与实验数据仅保存在`D:\3DGS`本地
- 路线说明：ADR-007后，本文“tile任务”统一解释为当前Gaussian内部的8×8 block
  遍历事务，不建立Gaussian–tile bin，也不执行逐tile排序。

## 1. 子系统边界

`raw_gaussian_projection_array`接收训练后Gaussian的世界坐标、归一化quaternion、
三轴scale、opacity和标签，输出按当前Gaussian覆盖的8×8 block展开的完整描述符。描述符包括：

- Gaussian/meta标签、opacity和相机深度；
- 屏幕均值、二维协方差和裁剪后bbox；
- PSD保持的Cholesky因子、coordinate/factor shift；
- block坐标、Gaussian block序列的first/last及数值错误标志。

## 2. 动态重构合同

| active mode | 启用lane | 用途 |
|---:|---:|---|
| 0 | 1 | 固定基线、低负载/低功耗模式 |
| 1 | 2 | 中等投影压力 |
| 2 | 4 | 高投影压力 |
| 3 | 钳位到物理lane数 | 软件错误安全处理 |

- 启用的是物理lane前缀，所有lane为相同RTL副本。
- 输入Gaussian按启用lane轮询分发。
- 输出仲裁一旦选择lane，就保持到当前Gaussian的`last`，因此Gaussian内部block序列不交叉。
- shadow模式只有在`epoch_boundary && all_idle`时变为active；在途任务期间保持pending。
- 固定基线与动态方案只允许lane数量不同，不允许改变数值格式、SRAM/带宽约束或算术。

## 3. ready/valid与配置稳定性

- 原始Gaussian只有均值和协方差两路都ready时才被原子接收。
- 两路元数据必须完全一致才能进入屏幕投影；不一致置数值错误并有SVA检查。
- 单lane用在途事务计数器给出idle，不能用单一busy位，因为流水线允许多事务重叠。
- view矩阵、translation、相机内参、near/far、图像尺寸和正则项必须保持到阵列排空；
  后续系统顶层应把这些配置和mode放在同一epoch提交域。

## 4. 验证状态

- 原始Gaussian单lane、调度器、epoch模式控制和两lane集成阵列均有独立自检查testbench。
- 当前总回归：19个SystemVerilog自检查仿真和74个Python unittest全部通过。
- RTL规模统计：32个`.sv`模块、约3505行；testbench为20个、约1627行。
