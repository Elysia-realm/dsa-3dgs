# 命令与相机描述符规格 v1

日期：2026-10-05  
生产顶层：`rtl/gs_accel_system_top.sv`  
描述符读取：`rtl/dma/axi4_camera_config_read_dma.sv`

## 1. 命令提交

软件先写 Gaussian、相机、属性和输出基址，再写图像尺寸与 Gaussian 数量，最后写
`CONTROL.START`。START 被接受时，顶层原子快照这些寄存器和当前模式；软件随后改写
shadow 寄存器不会改变正在执行的批次。

```text
GAUSSIAN_BASE   mean/GID 记录数组，16 Byte 对齐
CAMERA_BASE     camera descriptor v1，16 Byte 对齐
ATTRIBUTE_BASE  按 GID 索引的属性数组
OUTPUT_BASE     image-state/output backing store
IMAGE_SIZE      height[31:16], width[15:0]
GAUSSIAN_COUNT  当前批次记录数；允许 0
CONTROL         bit0 START, bit3 CONTINUE, bit4 MORE_BATCHES
```

生产默认 `USE_AXI_CAMERA_DMA=1`。兼容参数 `USE_AXI_CAMERA_DMA=0` 仅保留已有模块测试和
迁移用途，此时才从顶层静态 `cfg_*` 端口取相机值。

## 2. Camera descriptor v1

描述符固定为 224 Byte，即 28 个 64-bit word 或 14 个 128-bit AXI beat。内存采用
little-endian byte 顺序；AXI beat 的低 64 位是偶数 word，高 64 位是下一奇数 word。

| Word | 字段 | 有效位/格式 |
| ---: | --- | --- |
| 0–8 | world-to-camera R00…R22 | 低 22 位，signed Q1.20 |
| 9–11 | Tx、Ty、Tz | 低 27 位，signed Q10.16 |
| 12–14 | camera X、Y、Z | 低 27 位，signed Q10.16 |
| 15–18 | fx、fy、cx、cy | 低 33 位，signed Q16.16 |
| 19–20 | near、far | 低 27 位，signed Q10.16 |
| 21 | covariance regularizer | 低 35 位，unsigned Q*.8 |
| 22–24 | depth pivot0、1、2 | 低 27 位，signed Q10.16 |
| 25 | image width | 低 16 位；高 48 位必须为 0 |
| 26 | image height | 低 16 位；高 48 位必须为 0 |
| 27 | tag/version + Gaussian count | `[63:32]=0x47534301`，`[31:0]=count` |

硬件检查 16 Byte 对齐、AXI ID/RRESP/RLAST、tag/version、非零尺寸、`near < far`、
`pivot0 <= pivot1 <= pivot2`，并要求描述符中的尺寸和 count 与 START 时快照的 APB
寄存器一致。读取支持在 4 KiB 边界处分裂 burst，不跨越边界。

## 3. Continuation

fresh batch 接受后锁存下列逻辑帧不变量：

- 输出基址和图像尺寸；
- R、T、camera position、fx/fy/cx/cy、near/far、regularizer；
- active G/P/R/E 模式和 epoch。

continuation 会重新读取描述符。Gaussian count 和三个 depth pivot 允许随批次改变；上述
相机不变量必须逐字段完全一致。检查失败时拒绝启动 mean DMA 和计算核心，不增加 epoch，
关闭当前逻辑帧并报告完成错误。该逐字段比较强于只比较软件提供的哈希。

## 4. 错误与恢复

| ERROR_STATUS 位 | 含义 |
| ---: | --- |
| 8 | busy 时再次 START；当前工作继续，记录错误中断 |
| 18 | fresh/continuation 序列、输出基址或尺寸非法 |
| 19 | camera AXI ID/RRESP/RLAST 协议错误 |
| 20 | camera 对齐、tag、范围或描述符/APB count/尺寸错误 |
| 21 | continuation 相机配置与 fresh batch 不一致 |

描述符失败不会发出 mean、attribute 或像素事务。软件读取 `ERROR_STATUS` 后写
`CONTROL.STATUS_CLEAR`，修正描述符或命令后可重新提交。`SOFT_RESET` 还会取消未完成的
描述符命令并关闭 continuation 逻辑帧。

## 5. 主机示例

现有 workload 生成器会在 `camera.memh` 的 word27 写入 v1 tag。下面命令把它转换为
可放入 `CAMERA_BASE` 的 224 Byte 二进制，并生成按顺序执行的 APB 写事务：

```powershell
python scripts/build_rtl_real_workload.py --scene bonsai --count 4 --max-dimension 32 `
  --output experiments/t03_workload
python scripts/build_t03_command.py experiments/t03_workload/camera.memh `
  --gaussian-base 0x1000 --camera-base 0x2000 --attribute-base 0x4000 `
  --output-base 0x100000 --output experiments/t03_command_example
```

输出为 `camera_descriptor_v1.bin` 和 `command.json`。continuation 使用 `--continuation`，
非末批再加 `--more-batches`。2026-10-05 之前保存的历史 `camera.memh` 没有 v1 tag，
用于新生产路径时必须由当前生成器重建；不得在硬件中静默接受无版本旧格式。
