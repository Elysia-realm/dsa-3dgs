# RTL 验证日志：真实负载投影定点格式收敛

日期：2026-08-16  
数据策略：所有输入、trace、图像和报告仅保存在 `D:\3DGS`，未上传网络。

## 1. 本轮目标与架构边界

本轮只修复真实负载暴露的投影数值问题，不改变既定主数据流：

```text
深度分组
→ Gaussian 有序发射
→ Gaussian 内部 8×8 block 遍历
```

动态可重构 G/P/R/E、Gaussian 顺序退休、AXI 接口和 continuation 语义保持不变；没有引入 per-tile bin/list/sort 主路径。

## 2. 根因定位

旧版 Bonsai camera 146、64×43、batch0 的内部图像指标仅为：

```text
PSNR = 18.2222065737 dB
SSIM = 0.8839639002
```

SH 定点核和 alpha/blend 隔离实验均表明它们不是主误差源。对 256 颗 Gaussian 增加描述符 trace，并进一步增加 Cholesky 编码器入口协方差 trace 后，确认存在三类投影格式边界：

1. 屏幕协方差 32-bit Q24.8 对近裁剪面大 footprint 不足，真实值被饱和；
2. 透视 Jacobian 的 `j02=-fx*x/z^2` 超过原 32-bit signed Q*.16；
3. 三维协方差 41-bit Q24.16 的小数精度不足，小 Gaussian 经大 Jacobian 放大后可能失去正定性。

这解释了此前 `gid=606379` 等点出现 `L=[11585,11585,0], factor_shift=0` 的灾难性错误；Cholesky 除法缩放不是主根因。

## 3. 格式选择依据

### 3.1 屏幕协方差

完整扫描 Bonsai camera 146 的 1,051,092 颗有效 Gaussian：

```text
max cov00 Q8 = 20,145,641,472
max |cov01| Q8 = 4,358,051,840
max cov11 Q8 = 9,598,518,272
```

因此将屏幕协方差接口由 32-bit Q24.8 改为 35-bit Q27.8。35 bit 是该真实工作负载所需的最小安全总宽度。

### 3.2 透视 Jacobian

同一有效集合中：

```text
max |j02| Q16 = 2,549,914,624
```

原 32-bit signed 范围不足。实现采用 34-bit signed Q*.16，保留一个额外保护位。

### 3.3 三维协方差

在 batch0 上比较 41-bit 总宽度下不同小数位：

| 格式 | 非正定 Gaussian 数量 |
|---|---:|
| Q24.16 | 15 |
| 17 fractional bits | 6 |
| 18 fractional bits | 1 |
| Q21.19 | 0（浮点量化模型） |
| Q20.20 | 0 |

RTL 的 Q21.19 trace 仍有一颗极小残差边界 `gid=1054042`，因此最终采用 Q20.20。总位宽仍为 41 bit，没有扩大三维协方差存储或乘法器端口。

对本地 13 个场景扫描最大 scale 后，Q20.20 仍有足够整数动态范围；最大 scale 出现在 `treehill`，约 16.4433，对应协方差保守上界远低于 41-bit signed 范围。

## 4. 无效数值语义

上游数值无效不再伪装为“全屏 Gaussian”。

```text
真正数值无效
→ empty bbox
→ 单个 ordered culled 事件
→ 不进入 8×8 block 全屏遍历
```

合法的大 footprint 仍由正常 bbox clipping 覆盖全屏，不会被误删。Cholesky determinant、divider、residual 或 factor encoding 失败也采用 fail-closed，但保持 Gaussian 有序退休。
