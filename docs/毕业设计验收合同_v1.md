# 3DGS 动态可重构硬件加速器验收合同 v1

日期：2026-09-20；签核日期：2026-09-29。状态：**T00 已签核，作为后续实现与验收的冻结合同**。本合同把现有项目目标转成可复核的检查条件。任务入口为[毕业设计剩余任务执行清单](毕业设计剩余任务执行清单_2026-09-20.md)。任何目标删减、改为软硬件协同或降低验收层级，均须记录明确批准、日期及影响；开发者不得凭实现困难自行改写。

## 1. 已固定的设计与责任边界

1. 生产综合和系统验证顶层为 `gs_accel_system_top`；主路径为**深度分组 → Gaussian 有序发射/退休 → Gaussian 内部 8×8 block 遍历**。组内排序使用 `(depth, gid, sequence)` 稳定键；同像素前向混合按全局 Gaussian 顺序进行。G/P/R/E 动态重配置只在受影响状态排空的安全 epoch 边界提交。检查方式：生产配置的 RTL 仿真、随机重复深度与背压测试、连续帧/continuation 对拍；排序无重漏，固定/自动模式在相同数值配置下的最终 RGB/T 逐位一致。
2. **默认输入责任仍是硬件全场景调度。** 主机负责提供合法版本的 Gaussian 属性与相机、配置地址/数量/输出缓冲并启动；主机可以做与相机无关的模型文件解析和格式编码。硬件负责当前相机下的深度计算、全局有序分组、容量安全切分或片外流管理、有序渲染与最终 RGB DMA。主机不得在正式自主执行路径预先全局排序、生成 pivot 或按深度编批。软件 `lexsort` 只用作独立验证 oracle。现有完整场景演示使用软件预排序，故不算此目标通过。
3. 若未来用户明确批准 CPU 预处理，则修订本节和 T06，并用“软硬件协同”命名该分支；记录 CPU 的排序、分批、搬运及运行时耗时/字节数，端到端性能包含这些成本。未经批准不切换分支。
4. 本项目目标是 ASIC 评价。FPGA、RTL 周期、AST 算子数和事务数可作为功能/探索证据，不替代映射后 ASIC 面积、时序和功耗。

### GCC 论文标准比较基线（文献签核已完成）

用户指定 `参考文献/GCC.pdf` 作为本项目的**最终 PPA 对标目标**。本项目先按 D03–D05 的硬性通过线验收，再报告 300 MHz、2.7 mm²、0.8 W 目标线，最后在可比条件下评价是否超越 GCC；若工艺、存储或负载不能对齐，只能作归一化/条件化比较，不得用 45/55 nm 原始数值直接宣称超过 28 nm GCC。来源为 Pei 等，*GCC: A 3DGS Inference Architecture with Gaussian-Wise and Cross-Stage Conditional Processing*，MICRO 2025，arXiv:2507.15300v3；本地 PDF SHA-256 为 `CC61C8228E2015F725A9A78FF46D8A900FCB6EBFDC93AF17FAFFDE9F1C423E5B`。以下数值是论文报告值，不是本项目已实现值。

## 4. 性能、画质与物理量的统一测量方法

- **完整帧边界**：从主机提交合法 START/描述符后、硬件接受本帧开始，到最终 RGB DMA 写事务 B 响应完成且 DONE 可见为止；包括输入 DMA、深度分组/排序、投影、光栅、帧输出和必要的运行时预处理。另报 host 模型加载/格式编码、外部传输与等待；若批准 CPU 相机相关预处理，端到端时间必须加上它。`FPS = f_effective / N_frame_cycles` 仅在签核频率与 AXI 时序冻结后计算；多帧同时给每帧、平均及尾部统计，不能只取最优帧。
- **可比负载**：固定 D07 的场景/相机/模型/分辨率、输入顺序、数值格式、背压模型、输出格式和 RTL 哈希；对 fixed/dynamic、共享/旁路、排序、形状、提前终止和压缩分别改动唯一待比较因素。报告周期、阶段计数、字节、活动和错误，注明 candidate/default。无法保持同条件的比较不得计算“加速百分比”。
- **画质**：由 RTL RGB DMA 形成图像；与匹配 GT 使用相同尺寸、颜色空间、背景及有效像素 mask 计算 PSNR/SSIM/LPIPS。报告逐帧值、场景聚合与失败帧；D06 决定具体聚合规则和门槛。固定模式与动态模式、候选与未压缩基线的内部逐位/容差合同另测，不能代替 GT。
- **PPA**：列出工艺/库/工具/模型/脚本哈希、SS/TT/FF 的电压温度、SDC、时钟及 IO 约束；按 corner 给 WNS/TNS、setup/hold、门控检查；分别给综合标准单元、CACTI SRAM 和合计面积，以及内部、开关、漏电与合计功耗。活动由冻结完整帧 VCD/SAIF 等产生，并说明覆盖率和映射位置；`E_frame = P_activity × T_frame` 的功耗范围与 `T_frame` 口径必须一致。Ramulator/LPDDR4 的片外时间、流量和能耗单列，不把它计入 1 W 芯片核上限，也不能隐去它来宣称端到端能效。综合级数字不得称为 post-route。
- **容量与错误**：D05 的片上容量上限和 D07 最大场景共同约束 T06/T11；报告峰值驻留、最大 outstanding、片外读写量及容量溢出/错误恢复。任何静默丢 Gaussian、死锁、顺序违例、假剔除或时序违例均为失败，不受低收益停止优化规则豁免。

## 5. T00 签核状态与后续使用

本版已把每个必需目标连到可执行检查和后续任务，D01–D08 已由用户确认，**T00 于 2026-09-29 签核完成**。T01 负责锁定工具与库文件版本并取得首次映射，不因某个目标尚未实现而重开 T00；只有用户/导师改变验收范围，或后续发现条件不可执行时，才以新版本修订合同。达到某候选约 1% 以下边际周期收益、无面积/功耗收益证据且不影响硬性条件时，记录结论并冻结该候选；200 MHz、30 FPS、4 mm²、300 KB、1 W 和画质门槛不因此降低。
