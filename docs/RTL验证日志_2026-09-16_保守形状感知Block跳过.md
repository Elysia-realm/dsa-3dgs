# 2026-09-16：保守形状感知 8×8 block 跳过

## 目标与边界

本轮从 2026-09-15 的流式 Z 预处理轮次继续，保持
`depth_group -> ordered_gaussian_issue_retire -> per_gaussian_8x8_block_walk`
主路径和动态 G/P/R/E 配置不变。实现的是默认关闭的 `ENABLE_SHAPE_BLOCK_REJECT`
候选，不是改变排序、Gaussian 发射顺序或像素混合次序。仍未接通 R 共享 PE 客户端。

## 实现

- 新增 `rtl/raster/gaussian_shape_block_reject.sv`。先把 block 的 x/y 范围与 bbox、
  图像边界相交；空交集仍由原 empty/culled 路径处理。
- 对非空 block，使用所有像素共享的 `l11 * dy` 一轴下界。完整二次型另一轴平方非负；
  仅当一轴下界已经足以证明整块像素均低于 alpha 保留阈值时跳过。阈值按 opacity
  分段保守选取，判定失败则完全保留原逐像素路径；新增一个局部乘法运算符，面积/频率
  尚未测量。
- 判定放在 `ordered_block_raster_frontend` 的 block 输入握手处，而不是修改原 expander
  内部状态机；已接受的先前 block 仍继续退休。frame/system 顶层透传候选参数，
  `REAL_SHAPE` 计数暴露跳过数量。默认参数为 0。
- `scripts/run_shared_pe_validation.py` 同时保存原始帧存储摘要与 epoch 生效后的 RGB/T
  语义摘要。跳过的透明像素可能不写入当前 epoch，但渲染时这些位置仍是清空态；
  不能把语义等价写成原始存储逐 bit 相同。跨轮未启用候选的基线比较继续使用原始摘要。

## 验证结果

- 独立定点模型检查 opacity 阈值，并对 20,000 个随机 block 做“判定跳过后任一像素
  都不能通过 alpha 阈值”的检查；另有 RTL 定向测试，覆盖远/近/零 opacity/空 x/y。
- 六场景（Bonsai、Train、Garden、Truck、Room、Counter）× G/P/R/E × ideal/limited AXI
  × bypass/shared/shape 共 144 次 DMA 仿真通过。shape 48/48 语义图像与 bypass、shared
  相同，原始帧槽摘要则 48/48 与 shared 不同，差异是被省去的透明 epoch 写入。
- shape 相对共享基线 48/48 提速，平均节省 71.6875 周期，最少 4、最多 228；
  共跳过 384 个 block，减少 1704 次提交/写、1072 次状态读。
- 相对完整 bypass 仅 22/48 提速，平均仍慢 0.147017%，最差慢 7.032181%。
  因此性能对 bypass **未通过**，候选维持默认关闭，不能据此宣称能耗/面积改善。
- 与 2026-09-15 报告交叉审计：当前 shape 矩阵中的 96 项未启用候选的
  bypass/shared 基线，原始图像、工作量、PE 操作数和周期均未变化。
- 当前源码重跑正式 Bonsai/Train/Garden 96 项、Truck/Room/Counter 72 项默认/排序
  DMA 基线，以及排序 42 配置、147,343 输出和 374/374 定向非退化 case。
  顶层默认/候选 Verilator lint、Icarus 全回归和五类顶层展开均通过；Python 全回归
  150/150 通过。这些检查均不是工艺 PPA 或形式证明。

## 开发中发现并修复的问题

最初把 combinational reject 接入 block expander 内部，Icarus 出现 delta-cycle 不收敛；
已改为在外层握手时丢弃可证明空贡献 block。Verilator 还发现 Icarus 容忍的三目常量
词法问题，已修复并重跑顶层检查。增加非空几何交集守卫，避免把本来没有像素的 block
误计为形状拒绝。停止并清理了这次调试留下的精确匹配临时 `vvp` 进程；没有删除用户数据。
