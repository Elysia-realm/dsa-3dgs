# T05 BSU接口与共享资源规格 v2：空间流水

v2取代v1中的折叠生产配置；v1及2026-10-09实验保留为历史对照。生产顶层仍为
`gs_accel_system_top`，默认 `GROUP_CAPACITY=16`、`SORT_CAPACITY=16`、`BSU_PIPELINED=1`、
`USE_BITONIC_SORT=1`、共享G/P/R与最终RGB DMA开启。K8空间流水及K8/K16折叠均保留可配置。

## 接口与稳定性

QSU→BSU的ready/valid字段不变：signed depth、unsigned GID、sequence、group ID和group_last。
仅搬运描述符/属性索引；完整key相等时arrival ordinal维持输入顺序，无效尾项以正无穷补齐。
合法空组为valid+empty+last，按队列顺序通过并产生subset_done，不输出有效描述符。
超容量或组ID混用整组拒绝，报告sticky overflow；不输出部分排序结果。
T06必须产生容量以内、子集间全局有序的输入；BSU不擅自拆大组并冒充全局有序。

## 并行实现

- K16为10个物理流水层、每层8对CAS，整个网络80个逻辑CAS；第一层首对由共享PE的G
  客户端实际计算，其余79个CAS使用专用比较器。K8对应6层、每层4对、24个逻辑CAS。
- 两个输入组缓冲、逐层弹性寄存器和单描述符输出串化器，允许下一组收集、多个网络层
  以及上一组发出同时进行。输出停顿经ready逐级回传，数据和组边界稳定，不覆盖在途组。
- G请求发出前保证第一层可用，并为响应保留空位。等待G期间该空位不会被别的组占用；
  因而G不会持有共享PE的响应又等待下游P/R，避免形成资源等待环。
- 未使用批处理控制的动态索引去遍历整个网络，CAS连线在elaboration时静态确定。每层只有
  在有效token前进时更新数据寄存器；这不是已实现工艺级门控或已测功耗收益的声明。

## 时序与吞吐

在无PE竞争、无输出背压且输入持续有效时，饱和满组实测：K8每8拍、K16每16拍输出一组，
即输出端稳态1描述符/拍。统计不包含外部QSU或入口service gate限速；有限组/停顿会降低吞吐。
网络不再要求等上一组全部发完才收下一组。理论尾输入握手到首次输出valid为网络层数+1拍
（K8 7拍、K16 11拍）；理想ready常高时首次输出握手再晚1拍。吞吐测试计时起点下，首次
输出在第15/27拍；应使用相同起点比较，不将该数值直接当尾输入后的延迟。

| K | 架构 | 4比较lane预算下实测满组间隔 | 1比较lane预算下实测满组间隔 |
| --- | --- | ---: | ---: |
| 8 | 旧折叠 | 28 | 64 |
| 8 | 空间流水 | 8 | 8 |
| 16 | 旧折叠 | 72 | 192 |
| 16 | 空间流水 | 16 | 16 |

空间流水的专用CAS不随模式变成逐对串行；G/P/R/E仍调整共享PE权重/优先级、G入口服务率
以及P/SH/alpha实际lane使用。`cfg_active_lanes_i`作为接口兼容保留，**不直接改变空间网络
每层比较宽度**；该参数的分配效果由上游service gate实施。不能继续用v1的G比较4/2/1数量
描述空间网络。共享P执行深度及XYZ MAC，共享R执行old_T×alpha，其余专用边界仍同v1。

## 容量与资源

K16描述符字宽81 bit（含1bit生产占位payload、valid、到达序号），10层条目寄存器加双
输入缓冲共 `12*16*81=15,552 bit`，约1.90 KiB；K8为 `8*8*80=5,120 bit`。此数不含计数器
和控制，也不代表SRAM宏面积。双库映射将这些寄存器与互连实际计价，不以黑盒或零面积处理。

K16模块面积Nangate45 TT约0.1694 mm²、ICsprout55 TT约0.2304 mm²；K8约0.0596/0.0816 mm²。
本轮依据自然容量下40/40更快、平均节省3.365%整帧周期以及用户优先并行的要求选择K16，
同时保留明确的面积代价。最终芯片4mm²/1W/200MHz等硬线仍须T11/T12验证。

## APB工作计数

`SORT_CAPABILITIES` 0x084：bit0可计数，bit3 Bitonic，新增bit4空间流水，bit[31:16]=K；
生产K16读值为`0x00100019`。旧折叠模式bit4=0，旧统计语义保留。

空间流水模式下：

| 地址 | 语义 |
| --- | --- |
| 0x088 | G共享CAS请求数，每个提交的子集1次（空组也经过流水） |
| 0x08C | 专用CAS数，K16每组79次，含哨兵比较 |
| 0x090 | 实际交换数 |
| 0x094 | 有效流水层前进次数，K16每完整组10次 |
| 0x098 | 非空子集退休数 |
| 0x09C | 同一拍至少两个网络层前进的拍数（v1称fallback） |
| 0x0A0 | 输入描述符与输出描述符同拍握手次数（v1称phase_grants） |
| 0x0A4 | G共享比较请求等待拍 |

0x0A8–0x0B4的旧Odd-Even特有字段为0。软件须先读capabilities再解释0x09C/0x0A0，
不能把新计数当作串行fallback。快照、逻辑帧重置及continuation累计语义不变。

## 证据版本

选型实验为同一明确参数化版本：五场景、共同8项和自然16项子集、四模式与两种AXI，共240次。
随后只修改顶层默认容量为16，测试台释放容量/BSU/R/RGB参数覆盖，另跑40次默认生产验证，
周期与图像逐条匹配所选方案。前者源码保存在selection_snapshot，后者验证当前发布源码；
不得把前者的旧顶层默认值哈希写成当前值。
