# RTL验证日志：完整帧有序批次索引与Mean流

日期：2026-08-14

## 1. 目的

把完整帧continuation控制推进为可执行的本地DMA输入。生成器继续保持：

```text
RTL Q16深度分组 -> Gaussian有序发射 -> Gaussian内部8x8 block遍历
```

没有生成per-tile bin/list/sort。

## 2. 位精确排序键

新增`scripts/build_full_frame_batch_index.py`。排序不使用普通FP32 camera depth，
而是复现RTL `gaussian_depth_prepass_core`：

1. world mean量化为signed Q10.16/27-bit；
2. 与相机第3行Q2.20/22-bit旋转系数和Q10.16 translation做整数乘加；
3. 右移20位，半LSB远离0舍入；
4. 用near/far和overflow合同筛选；
5. 按`(depth_q16, unsigned global_gid)`稳定排序。

因此软件批次边界与RTL实际分组键一致，避免浮点深度近邻在硬件中重新翻序。

## 3. 容量安全pivot构造

生成器把相同`depth_q16`视为不可由深度pivot拆分的run。每组不超过
`GROUP_CAPACITY`，每批最多4组：

- 正常run在不超过容量时合并进当前组；
- 新run放不下时关闭当前组并建立下一组；
- 四组用满后关闭批次；
- 单个同深度run超过容量时，只能在批次边界按容量切段，避免同一批内两个组
  无法用严格小于pivot区分。

生成后会从实际pivots重放`depth_group_buffer`的三个比较，逐批确认观察到的四组
计数与manifest一致且均不超过容量；同时检查全索引连续覆盖、深度非降和同深度
GID非降。

## 4. Bonsai完整索引产物

目录：`experiments/full_frame_batches/bonsai_cam_mid_d64_c256`

- 训练Gaussian：1,244,819；
- RTL深度有效：1,051,092；
- 分辨率：64x43；
- group容量：256；
- 批数：1030；理想下界为`ceil(1051092/1024)=1027`，只多3批；
- 最大batch：1024；最大group：256；
- 平均四组容量利用率约99.656%；
- global GID保持原始PLY索引，现有attribute DMA会按
  `ATTRIBUTE_BASE + GID*144`读取，不需frame-local remap。

文件：

- `depth_gid_index.bin`：8,408,736 byte，little-endian `{uint32 GID,int32 depth}`；
- index SHA-256：
  `14e1a02a5d745bd84b6a74c3afea8fed39f6b69dc9fc44f3c1683370f32b4562`；
- `mean_stream.bin`：16,817,472 byte，1,051,092个RTL 128-bit mean record；
- mean SHA-256：
  `ef632192eea0830e692fccaf59444b5231b6607ab1f8c8cd75f044a450e3ad58`；
- `manifest.json`：每批包含offset/count、pivots、group counts、fresh/continue/
  more-batches控制位和mean byte offset。

mean stream生成后会重新解码对应PLY mean并重算RTL depth，要求与索引逐项完全
相同；任何偏差会终止生成，不会把损坏输入交给长时间仿真。

## 5. 验证

- 完整帧索引/容量/mean打包单元测试加入后，Python共100项PASS；
- 独立复核bonsai：1,051,092项全局顺序正确、1030批pivot重放全部匹配、0个
  group overflow；
- mean DMA读取记录内32-bit GID；attribute DMA地址合同确认是global GID乘144；
- 本子阶段没有修改RTL；上一阶段的Icarus 62项+1综合入口及默认/4+4 Verilator
  lint结果保持有效。

## 6. 当前边界和下一步

当前生成了完整mean索引和流，但尚未生成/连接完整属性仿真存储，也未执行1030批
RTL完整帧。因此仍不能报告完整帧FPS或PSNR/SSIM/LPIPS。

下一步实现sparse global-GID attribute仿真后端：只为索引中的eligible GID生成
或按需读取9个128-bit attribute beat，避免为了测试复制完整dense属性空间。先用
bonsai第1批1024 Gaussian验证pivots、global GID attribute寻址和frame state，再
扩展到跨批continuation和完整1030批。
