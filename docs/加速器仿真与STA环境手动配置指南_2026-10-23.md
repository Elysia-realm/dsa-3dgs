| 文中标识 | 怎么打开 | 典型路径 |
|---|---|---|

- Windows `D:\3DGS` → Ubuntu `/mnt/d/3DGS`。
- MSYS2 中的 `/d/3DGS` 不等于 Ubuntu 路径；在 Ubuntu 应改用 `/mnt/d/3DGS`。

Linux 文件系统通常更适合 Linux 编译的大量小文件访问；跨系统共享输入可以通过 `/mnt/d`。这是微软官方推荐的文件系统使用方式。[微软文件系统说明](https://learn.microsoft.com/en-us/windows/wsl/filesystems)

## 3. 安装并验证 WSL2 / Ubuntu

### 3.1 检查虚拟化

打开任务管理器 → 性能 → CPU，查看“虚拟化”。若显示“已启用”，先继续安装，不必改 BIOS。

若显示“已禁用”，或安装后报虚拟化不可用：Windows 设置 → 系统 → 恢复 → 高级启动 → 立即重新启动 → 疑难解答 → 高级选项 → UEFI 固件设置。在固件中启用 Intel Virtualization Technology / VT-x。菜单因具体机型不同，请按机型厂商手册定位；本机主板标识为 HP 89B3，不能仅凭该标识给出可靠的固定菜单路径。只改相关虚拟化选项，保存后重新进入 Windows 核对。

### 3.2 安装

**Windows 管理员 PowerShell：**

```powershell
wsl --install -d Ubuntu-24.04
```

若要求重新启动，保存工作后重启。重启后打开 Ubuntu，按提示创建 Linux 用户名（例如 `gsdev`）和密码。输入密码时终端不显示星号，这是正常行为；此密码用于 `sudo`。

安装程序下载卡住时，先确认没有已完成安装的发行版，再按官方方式尝试：

```powershell
wsl --list --online
wsl --install --web-download -d Ubuntu-24.04
```

若在线列表的名称有变化，使用列表中 Ubuntu 24.04 对应的准确名称；后文发行版名也同步替换。不要反复安装不同名字的 Ubuntu 副本。[微软安装步骤](https://learn.microsoft.com/en-us/windows/wsl/install)

### 3.3 核对 WSL 版本

**Windows 普通 PowerShell：**

```powershell
wsl --update
wsl --version
wsl --status
wsl --list --verbose
```

成功判据：能看到 Ubuntu-24.04，`VERSION` 列为 **2**，可以进入 Linux shell。如果为 1：

```powershell
wsl --set-version Ubuntu-24.04 2
```

首次安装默认位置即可；当前 C 盘空间足够。暂不增加移动 VHDX/导入导出操作。

### 3.4 设置 WSL 资源上限

**Windows 普通 PowerShell：**

```powershell
notepad.exe "$env:USERPROFILE\.wslconfig"
```

若已有文件，保留原有必要配置，只合并以下设置，不重复写第二个 `[wsl2]` 段。保存为 `.wslconfig`，不是 `.wslconfig.txt`：

```ini
[wsl2]
memory=20GB
processors=10
swap=8GB
```

这是针对当前 32 GiB 主机的起始配置。综合内存不足时先减少并行；确认 Windows 余量后才考虑提高到 24GB。swap 是应急余量，持续大量交换会非常慢。

关闭正在运行的 WSL 工作后，在 PowerShell 执行：

```powershell
wsl --shutdown
wsl -d Ubuntu-24.04
```

`--shutdown` 会停止所有 WSL 发行版，运行长任务期间不要执行。进入 **Ubuntu Bash** 后：

```bash
cat /etc/os-release
uname -r
nproc
free -h
df -h ~ /mnt/d
test -d /mnt/d/3DGS && echo PROJECT_PATH_OK
```

成功判据：Ubuntu 24.04、WSL2 内核、约 10 个可用处理器、内存上限接近设置值、出现 `PROJECT_PATH_OK`。[微软 WSL 配置文档](https://learn.microsoft.com/en-us/windows/wsl/wsl-config)

## 5. 从官方源码安装 OpenSTA

建议源码安装并保留提交 SHA，而不是假定 Ubuntu 自带 `opensta` 包具备项目所需的所有命令。OpenSTA 官方构建依赖包含 CUDD、Tcl、Eigen、SWIG 等，不能只安装 CMake/GCC。[OpenSTA 官方构建说明](https://github.com/parallaxsw/OpenSTA)

以下首次安装命令假定 `~/eda/src/cudd` 和 `~/eda/src/OpenSTA` 尚不存在。重试时不要删除原目录；先检查原日志和目录状态。

### 5.1 安装 CUDD 3.0.0

```bash
set -euo pipefail
cd ~/eda/src
git clone --branch 3.0.0 --depth 1 https://github.com/cuddorg/cudd.git cudd
cd cudd
git rev-parse HEAD > ~/eda/logs/cudd.commit.txt
./configure --prefix="$HOME/eda/opt/cudd-3.0.0" 2>&1 | tee ~/eda/logs/cudd-configure.log
make -j4 2>&1 | tee ~/eda/logs/cudd-build.log
make check 2>&1 | tee ~/eda/logs/cudd-check.log
make install 2>&1 | tee ~/eda/logs/cudd-install.log
test -s ~/eda/opt/cudd-3.0.0/include/cudd.h
test -s ~/eda/opt/cudd-3.0.0/lib/libcudd.a
```

`set -euo pipefail` 使失败不能被 `tee` 掩盖；失败时 shell 可能退出，重新打开 Ubuntu 后从失败步骤处理。官方提供 `make check` 作为自检。[CUDD 构建说明](https://github.com/cuddorg/cudd/blob/3.0.0/README)

成功判据：编译、测试、安装都无失败；两个 `test` 成功。不要在 `make check` 失败时继续宣称 CUDD 安装验收通过。

### 5.2 编译 OpenSTA 并冻结本次源码

```bash
set -euo pipefail
cd ~/eda/src
git clone https://github.com/parallaxsw/OpenSTA.git OpenSTA
cd OpenSTA
git checkout --detach HEAD
git rev-parse HEAD > ~/eda/logs/opensta.commit.txt
git status --porcelain > ~/eda/logs/opensta-working-tree.txt
cmake -S . -B build -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DCUDD_DIR="$HOME/eda/opt/cudd-3.0.0" \
  -DCMAKE_INSTALL_PREFIX="$HOME/eda/opt/opensta" \
  2>&1 | tee ~/eda/logs/opensta-configure.log
cmake --build build --parallel 4 2>&1 | tee ~/eda/logs/opensta-build.log
cmake --install build 2>&1 | tee ~/eda/logs/opensta-install.log
test -x ~/eda/opt/opensta/bin/sta
~/eda/opt/opensta/bin/sta -version
```

这里冻结的是**你首次下载时实际取得的提交**，并非本指南已经验证过的固定二进制版本。GitHub 接口/连接在本机不稳定，本次未取得并实际编译一个可承诺的 OpenSTA SHA。今后复现应 checkout `opensta.commit.txt` 中的完整 SHA，不再追踪分支最新版本；保留源码目录或归档。

成功判据：CMake 找到 CUDD 的库和头文件、Eigen、Tcl、SWIG；构建和安装成功，`sta -version` 返回版本。

## 8. 安装 Ramulator 并验证 LPDDR4

本项目合同明确要求 LPDDR4。本指南采用 **CMU-SAFARI 原版 Ramulator（1.x 仓库）**，因为其官方仓库直接提供 LPDDR4 实现和 `configs/LPDDR4-config.cfg`，可以给出可核对的具体步骤。作者也发布了 Ramulator 2.0；若后续选择 2.0，需要重新核实所选提交的 LPDDR4 实现和配置，不能把 LPDDR5 示例改名后使用。[官方支持列表与用法](https://github.com/CMU-SAFARI/ramulator)

```bash
set -euo pipefail
cd ~/eda/src
```

T11 必须补的接入工作：

- 将各 AXI DMA 端口接到共同的物理地址空间、控制器/带宽预算，检查完整输入、暂存和输出区域不重叠。
- 定义 AXI beat/burst 到 DRAM 请求粒度的拆分/合并、读写仲裁、排队与最大在途数。
- 正确处理加速器时钟与 DRAM 时钟换算，完成回调与 AXI 背压、读数据、写响应时机。
- 在真实闭环仿真中让内存延迟影响 RTL；只离线重放 trace 的耗时不能直接当作加速器整帧时间。
- 检查帧末所有写响应/事务排空、错误恢复和非空连续帧。

Ramulator 主要提供 DRAM 时序行为；安装它不能自动补齐 LPDDR4 能耗报告。如 T11/T12 要求片外能耗，需另外冻结兼容的能耗模型/器件参数，单独报告，不能混入 1 W 芯片核功耗线。

## 9. 工艺库准备：软件之外的必要输入

### 9.1 复用并核对已有四个 Liberty

**Windows 普通 PowerShell：**

```powershell
Set-Location D:\3DGS
$manifest = Get-Content -LiteralPath 'asic/reports/t01/toolchain_manifest.json' -Raw | ConvertFrom-Json
foreach ($lib in $manifest.libraries) {
    if (-not (Test-Path -LiteralPath $lib.path)) { throw "Missing library: $($lib.path)" }
    $actualHash = (Get-FileHash -LiteralPath $lib.path -Algorithm SHA256).Hash
    if ($actualHash -ne $lib.sha256) { throw "Library hash mismatch: $($lib.path)" }
    [pscustomobject]@{PDK=$lib.pdk; Corner=$lib.corner; SHA256=$actualHash; Result='MATCH'}
}
```

成功判据：四行 `MATCH`，分别是 Nangate45 TT 和 ICsprout55 TT/SS/FF。文件不匹配时查明来源与版本，不能直接修改清单哈希来让检查通过。

### 9.2 补齐 Nangate45 SS/FF

优先从 [Si2 / Silvaco 官方 Open Cell 与 FreePDK 申请页](https://si2.org/open-cell-and-free-pdk-libraries/) 获取完整 45nm 标准单元库。学校用户按页面提交申请；保留邮件下载来源、许可与原始压缩包。也可通过导师/实验室已获授权的完整包取得。

需要的是同系列标准单元的 **Liberty NLDM** 文件，常见名称包括 `NangateOpenCellLibrary_typical.lib`、`NangateOpenCellLibrary_slow.lib`、`NangateOpenCellLibrary_fast.lib`；实际文件名与 PVT 以下载包内容为准。

注意：NCSU FreePDK45 的晶体管 HSPICE nominal/fast/slow 模型，不等于可直接输入 OpenSTA 的标准单元 Liberty；只下载基础 PDK 不能自动补齐这项。[NCSU FreePDK45 说明](https://eda.ncsu.edu/freepdk/freepdk45/)

把新包保存在独立版本目录，例如 `D:\3DGS\tmp\toolchains\freepdk45_full\<真实发布版本>`。随后核对：

1. 来源、版本、许可、完整 SHA-256；旧 TT 文件和历史结果保持可追溯。
2. Liberty 的 `nom_voltage`、`nom_temperature`、`operating_conditions`、单位与角定义。
3. 三个角的 cell 名称、pin、逻辑功能相容，覆盖网表中所有单元；不能混入另一套库。
4. 在每角实际执行 `read_liberty`、链接、时序检查；出现缺单元/缺弧时闭环。
5. 如果新包 TT 与原 TT 不同，决定使用新包完整三角并重新映射/验证，不偷偷混用。

当前没有可保证立即匿名下载且已经与本项目 TT 完整匹配的 SS/FF 包，故这项仍是外部资料依赖。取得一个文件并不自动获得三角验收；不能把 TT 文件复制改名成 SS/FF。

## 10. 安装成功后，怎样恢复 T01 的真实 STA

### 10.1 先明确分析版本

原 T01 四组网表属于 **2026-10-03** 源码，当前已到 T06 正式配置。旧网表可以用于历史复现或工具接入诊断，但不能作为当前 RTL 的时序/面积证据。

当前生产参数应以 `verification/t06_release_profile.json` 及对应发布证据为入口核对。`asic/scripts/run_t01_matrix.ps1` 只描述旧 T01 的 shared_baseline/alpha_only TT 矩阵；仅换成最新源文件不等于选中了当前生产参数。必须补齐参数传递、存储清单和当前版本映射检查。

重新分析应另建输出目录，例如 `asic/reports/t01_resume_20261023/`。不要直接执行旧矩阵覆盖原 `asic/reports/t01/runs/`。单次综合脚本已提供 `--output-root`；工程接入时同时审查其他缓存/汇总路径，保留旧证据。

### 10.2 缓存黑盒是当前顶层 STA 的实质阻塞

现有 `asic/scripts/run_t01_sta.tcl` 要求三个实际文件：

| 环境变量 | 必须指向什么 |
|---|---|
| `T01_LIBERTY` | 该角真实标准单元 `.lib` |
| `T01_NETLIST` | 对应源码/参数和映射版本的门级 Verilog 网表 |
| `T01_MEMORY_LIBERTY` | 与网表缓存边界单元名、pin/bus、端口时序和延迟行为相匹配的真实/有依据的抽象模型 |

历史流程把整个 `image_state_cache_backend`（包括控制逻辑）排除。不能拿一块普通 SRAM 的 `.lib` 顶替整个缓存模块，也不能创建空壳、零延迟或只有 cell 名的文件绕过脚本。

工程上建议在 T11 将缓存控制器留在综合内，只把具体 SRAM 数组作为明确宏边界；根据 CACTI/可用宏模型建立匹配端口与延迟的封装、仿真模型和时序抽象，逐项记录模型来源、覆盖范围及局限。若先采用整个缓存的暂时时序抽象，必须覆盖真实控制路径，并显式保留面积/功耗缺口。

因此，**你手动安装到第 8 节后，可以完成工具环境准备；不需要自己凭空编写缓存 Liberty。** 缓存边界是后续 RTL/约束/建模工作，需要在项目中实现和验证，不能作为“用户少安装一个软件”继续搁置。

### 10.3 输入具备之后的运行形式

以下是后续工程接入说明，不是当前可以直接复制运行成功的步骤。先用真实文件设置上述三个环境变量，路径均用 Linux 格式，再运行：

```bash
source ~/eda/env.sh
cd /mnt/d/3DGS
export T01_CLOCK_MHZ=200
test -s "$T01_LIBERTY"
test -s "$T01_NETLIST"
test -s "$T01_MEMORY_LIBERTY"
set -o pipefail
mkdir -p ~/work/t01-sta-resume
sta -no_init -exit asic/scripts/run_t01_sta.tcl \
  2>&1 | tee ~/work/t01-sta-resume/sta.log
```

同时按对应库设置 `T01_DRIVER_CELL`、`T01_LOAD` 并核对单位；I/O 电气约束不能为了让脚本跑通而留空。TT 历史驱动/负载值记录于 `asic/scripts/run_t01_matrix.ps1`，复用前核实预算和单位。

脚本已有的 5% uncertainty、10% I/O delay 是初始预算，还需 T11 接口/时钟/复位合同确认。恢复/撤除检查、setup/hold、slew/cap、所有端点约束、未解析单元、latch/组合环/多驱动均需审查。日志末尾 `T01_STA_REPORT_END` 不是通过标志，退出码为零也不能单独签核。

对每工艺 SS/TT/FF 检查相关 max/min 路径，不只检查 SS setup。200 MHz 对应 5ns 是约束，不代表满足；300 MHz 与 1GHz 分别是目标/冲刺线。综合网表的理想时钟 STA 不含提取布线寄生，报告中必须标明。

## 11. 活动功耗、仿真与性能验收还需要哪些东西

| 能力 | 工具是否已覆盖 | 项目侧仍需落实 |
|---|---|---|
| 功能仿真/接口验证 | 原 Windows Icarus/Verilator；本指南增加 Linux 冒烟 | 当前生产顶层及开关、协议/错误/恢复、真实五场景验证 |
| 标准单元综合 | 原 Windows Yosys/ABC | 当前生产参数、全顶层映射、未知单元审计、面积台账 |
| STA | 新增 OpenSTA | 全部真实库角、缓存边界、完整 SDC、约束覆盖、违例闭环 |
| 标准单元功耗 | OpenSTA VCD/SAIF 读取及功耗命令 | 带功耗表的 Liberty、代表性活动、正确实例 scope/信号映射、annotation 覆盖率 |
| SRAM | 新增 CACTI | 每个数组的组织/容量/延迟/能耗、控制器成本、工艺假设 |
| 外存时序 | 新增支持 LPDDR4 的 Ramulator | 共享控制器/带宽、AXI 桥接、真实闭环背压和时钟换算 |
| 目标画质 | 当前 NumPy/Pillow 是基础 | 原生分辨率、匹配 GT、正式 PSNR/SSIM/LPIPS 脚本和依赖版本 |

RTL 的 VCD 信号层次通常不等于映射后网表。不能直接加载一个 RTL 波形，看到功耗数字就称为有效活动功耗；需要有效映射或使用适当的门级活动，并报告未标注比例和默认活动假设。使用门级仿真时还需匹配标准单元 Verilog 功能模型；若要时序回标，还需工具和模型对 SDF 的支持核验，不能把本指南的零延迟小模型用于生产门级验证。

功耗报告分列 internal / switching / leakage / SRAM，明确是否包含时钟网络、I/O 和外存；缺项记录未测。完整模型连续仿真可能产生巨大 VCD，应预先规划有代表性的采样窗口并保留覆盖依据，不默认整帧所有层级无限 dump。

真实验收遵守当前项目纪律：本轮至少 Bonsai、Counter、Room、Train、Truck，同版本同口径；Kitchen/Garden 暂缓不等于最终免验。图像来自 RTL RGB DMA；T10 最终仍为 13 场景、每场景至少 5 视角及匹配 GT。记录整帧周期、阶段工作/等待、G/P/R 争用、QSU/BSU、DMA 事务和字节、合成与缓存统计。

主机墙钟/CPU 时间、RTL 周期、通过 STA 的频率下估算帧时/FPS、实测硬件性能分别列示。WSL 仿真跑得更快只说明宿主执行速度改善，不能算加速器 FPS 改善。

## 12. 常见故障与处理顺序

| 症状 | 处理 |
|---|---|
| WSL 报 `0x80370102` / 虚拟机启动失败 | 先检查任务管理器虚拟化、UEFI 设置和重启；按微软排错检查 Virtual Machine Platform 与 hypervisor 启动配置 |
| WSL 组件未启用 | 管理员 PowerShell 启用下方 Windows 功能后重启，再重新安装/启动发行版 |
| 下载卡在 0% | 使用官方 `--web-download`；核查代理/网络；不要用删除发行版作为下载重试手段 |
| Linux `git clone` 超时/EOF | 先确保该终端 `git ls-remote` 成功；确认代理、DNS 和系统时间，恢复后在新目录重试不完整下载 |
| `externally-managed-environment` | 用第 4 节 venv；不要执行 `sudo pip install` 或强行改系统 Python |
| CMake 找不到 CUDD | 检查第 5.1 节两个文件和 `-DCUDD_DIR`；确认路径是 Ubuntu 的 `/home/...`，不是 Windows 路径 |
| CMake 找不到 Tcl/Eigen/SWIG | 核对 `tcl-dev`、`libeigen3-dev`、`swig` 是否安装完成；检查 CMake 日志 |
| 编译进程显示 `Killed` | 可能内存不足，检查 `free -h`/`dmesg`，改为 `--parallel 2` 或 `make -j2`，先不要盲目提高并行 |
| Bash 报 `$'\r'` / bad interpreter | 新增脚本转 LF：在副本上 `sed -i 's/\r$//' 脚本名`；不要批量改生产源码 |
| OpenSTA `invalid command name` | 比较实际 `help` 与现有 Tcl；记录工具 SHA 和错误，不删除检查命令来制造 PASS |
| 缺 `T01_MEMORY_LIBERTY` | 第 10 节项目模型尚未完成；安装软件无法消除这个错误 |
| `No paths found` / unconstrained | 检查顶层、clock pin、库单元、顺序单元和 I/O 约束；不能视为“没有违例” |
| Windows 直接启动 Yosys 无输出/缺 DLL | 使用原项目脚本配置 OSS CAD Suite `bin`/`lib` PATH 和 `YOSYSHQ_ROOT`，不要随意下载 DLL |
| 普通 MSYS 找不到 Verilator | 用 UCRT64 或显式设置 `MSYSTEM=UCRT64`；本次核查已确认该区别 |
| Verilator 编译时报 `python3: command not found` | Windows UCRT64 按第 11 节补 Python；Ubuntu 检查第 4 节 `python3` 安装。显示 Verilator 版本不能替代编译自检 |

仅在 WSL 安装错误确实指向组件时，**Windows 管理员 PowerShell** 执行：

```powershell
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
```

然后手动重启。若 hypervisor 被手动禁用，按微软排错核对启动设置后再处理，不默认改 BIOS 或关闭其他安全功能。[微软 WSL 故障排查](https://learn.microsoft.com/en-us/windows/wsl/troubleshooting)
