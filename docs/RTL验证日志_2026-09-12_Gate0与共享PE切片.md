# RTL验证日志：Gate 0事实基线与首个共享PE切片

日期：2026-09-12

## 1. 本轮目标

按照 `当前实现全量审计与修订开发规划_2026-09-11.md`，本轮先完成 Gate 0 的机器可检验
事实基线，再启动 Gate 1。固定主路径保持为：

```text
深度分组 → Gaussian有序发射/退休 → Gaussian内部8×8 block遍历
```

没有加入 per-tile bin/list/sort，也没有修改现有 framebuffer 数值路径。

## 2. Gate 0：事实状态合同

- `camera_base` 尚未驱动相机描述符DMA；

- 自动模式功能闭环PASS，但策略性能NOT PASS；

新增 `verification/test_implementation_status.py` 的5项测试，将上述状态与生产filelist、
系统顶层源码及13场景真实标定报告交叉核对。这样后续只有实现与状态文件同步变更，测试才会

非生产属性。

## 3. Gate 1起点：共享compare/MAC PE

新增 `rtl/control/shared_reconfigurable_pe_slice.sv`。该模块只实例化一个结果寄存器和一套
可重构计算选择：

- compare模式执行稳定排序键 `(signed depth, unsigned gid, unsigned sequence)` 的小于判断；
- MAC模式执行有符号全精度 `lhs * rhs + acc`；
- G/P/R三个客户端共享同一数据通路；
- `group_weight/projection_weight/raster_weight`控制每轮服务credit；
- `shared_owner`控制每轮优先起点，credit耗尽后由round-robin保证其余请求不会永久饥饿；
- 单项elastic响应寄存器在下游背压时逐bit保持，并阻塞全部新请求；
- 输出各客户端grant、stall、总utilization、busy和clock-enable边界；
- `reconfigure_i`在安全epoch切换时清空旧credit；SVA要求重配置时响应已经排空；
- `aggressive_clock_gate`只形成clock-enable/operand-isolation边界，不直接门控RTL时钟。

这已经是可综合的真实共享compare/MAC物理切片，不是只有owner字段的控制占位符。但是它
尚未替换 `stable_group_sorter` 或投影/光栅中的现有算子，因此当前仍只能判为“PE复用
PARTIAL”，不能宣称系统主链已经完成跨阶段PE复用。

## 4. 新增定向验证

`tb_shared_reconfigurable_pe_slice.sv`覆盖：

1. G/P/R同时请求时2:1:1 credit和G owner的服务顺序；
2. 投影客户端负数MAC结果；
3. depth相等时按gid、sequence稳定决胜；
4. raster响应背压期间结果保持、所有新请求阻塞，以及同拍elastic replacement；
5. E式aggressive gate在空闲时拉低clock-enable、有请求时自动唤醒；
6. 模式切换显式清空旧credit。

## 5. 回归结果

- Python unittest：113/113 PASS（原108项，加5项事实状态合同）；
- Icarus Verilog 12：65个SystemVerilog自检 + 1个综合入口全部PASS；
- Verilator 5.050：`gs_accel_system_top`完整顶层lint PASS；
- Verilator 5.050：`shared_reconfigurable_pe_slice`独立lint PASS；
- 新增PE独立lint只有既有风格的`SYNCASYNCNET`复位/SVA告警，无Error、LATCH、
  MULTIDRIVEN或UNOPTFLAT失败；
- 现有真实4-Gaussian DMA微负载保持602 cycles、68 commits，说明生产渲染路径未改变。

## 6. 本轮状态与下一检查点

Gate 0已经完成。Gate 1完成了“运算/端口/精度合同”和“独立共享PE+仲裁+计数脉冲”，但
生产集成尚未完成。下一轮应先选择侵入最小、可逐bit对拍的接入点：

1. 为 `stable_group_sorter` 增加外部compare请求/响应适配器，先让G客户端结果真正决定插入位置；
2. 在投影路径选择一个明确的signed MAC替换点接P客户端；
3. 将mode table的weight/owner/gate和`mode_commit_pulse`接到共享切片；
4. 将grant/stall/utilization计入系统/APB可观测计数；
5. 用原插入排序/投影结果作为bypass golden，逐bit验证后再删除重复算术资源。

只有至少G、P两个生产客户端共用同一实例，并在四模式真实负载中出现可测grant/stall，
Gate 1才可判为PASS。
