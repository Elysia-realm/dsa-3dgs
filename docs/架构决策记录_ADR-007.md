# ADR-007：采用Gaussian-wise有序渲染与动态可重构联合主路径

- 日期：2026-08-04
- 状态：已接受，替代传统Gaussian–tile bin与逐tile排序路线
- 依据：开题报告的Gaussian-wise目标、本地GCC论文分析、现有动态投影与终止RTL

## 决策

本课题不以复现GCC为最终目标。完整加速器正式冻结为两层联合设计：

1. **数据流层**：参考GCC，采用Gaussian-wise有序渲染，消除tile-wise重复加载和排序。
2. **硬件层**：本课题重点，在保持Gaussian顺序和数值等价的前提下，按epoch动态调整
   depth/group、projection、SH和block raster资源份额，以适应跨场景和组间负载变化。

数据流为：

```text
Gaussian深度预计算
  → 全局粗粒度深度分组
  → 组内稳定排序
  → Gaussian前到后有序发射
  → 投影、SH与有效区域生成
  → 当前Gaussian内部8×8块遍历
  → 块内64像素alpha/blend/提前终止
  → 当前Gaussian全部块提交完成
  → 发射下一Gaussian
```

不再建设以下传统tile-wise主路径：

```text
Gaussian投影
  → 建立Gaussian–tile KV/bin
  → 按tile读取Gaussian列表
  → 每tile独立深度排序
  → tile-wise光栅
```

## 术语冻结

- **Gaussian-wise**：Gaussian是全局调度、属性加载和有序退休单位。
- **Gaussian block**：当前Gaussian有效区域内的一个8×8像素块，是空间遍历和并行计算单位。
- **block walker**：枚举当前Gaussian覆盖块的模块；现有`gaussian_tile_task_gen`在后续重构中按此语义使用。
- **tile/bin**：保存多个Gaussian与固定屏幕tile关联关系的长期KV结构；本方案主路径禁止使用。
- **排序**：只允许全局深度分组和组内稳定排序，不进行每tile重复排序。

## 正确性合同

1. Gaussian必须按照前到后深度顺序进入可见性相关的blend提交域。
2. 投影和SH可以并行或乱序计算，但必须通过sequence ID/有序完成缓冲按顺序退休。
3. 一颗Gaussian的所有有效8×8块必须完成或被终止表安全跳过，才能退休该Gaussian。
4. 后继Gaussian访问同一块或像素时，不得越过尚未提交的前驱；由有序发射和必要的
   block scoreboard共同保证。
5. 提前终止只能减少当前Gaussian的块/像素工作，或在全局条件满足时跳过更深组；
   不得改变剩余Gaussian的相对深度顺序。

## 动态可重构合同

- 动态模式在安全epoch边界低频切换，不能逐Gaussian改变模式。
- 可动态配置projection lane、SH资源、block walker/alpha资源和共享队列/SRAM bank份额；
  depth grouping与sorting资源也可在帧首阶段复用投影比较器/MAC阵列。
- 固定基线和动态模式共享相同的深度顺序、Gaussian描述符、数值格式、SRAM容量和带宽约束。
- 多投影lane仅允许提高前端预计算并行度，不能直接把乱序完成结果送入blend。
- 动态切换不得修改排序精度、alpha阈值、bbox边界或提前终止语义。
- 物理资源总量固定，所谓重构是时分复用、lane启停、仲裁权重和bank/队列份额改变，
  不是在运行时增加硬件面积。

### 联合模式的初步定义

| 模式 | 典型Gaussian-wise瓶颈 | 资源倾向 |
|---|---|---|
| G：group/sort priority | 帧首Gaussian多、分组拥塞 | 比较器/MAC优先服务depth和group sort |
| P：projection priority | 可见Gaussian多、投影队列积压 | 启用更多projection lane |
| R：raster priority | 大Gaussian或有效块多 | 更多block walker/alpha份额，projection限流 |
| E：energy saving | 遮挡强、深层组大量跳过 | 关闭空闲lane，保持最小吞吐资源 |

以上模式不是改变GCC式数据顺序，而是改变同一Gaussian-wise流水各阶段的服务能力。

## 理由

- 避免同一Gaussian覆盖多个tile时重复加载属性。
- 避免建立、搬运和查询Gaussian–tile KV映射。
- 避免每个tile重复深度排序。
- Gaussian属性、SH颜色和Cholesky参数可在其全部有效块之间复用。
- 与现有块级/像素级提前终止、图像状态和blend RTL兼容。
- 相比仅在投影前端Gaussian-wise、后端仍tile-wise的混合路线，更符合课题研究目标。
- GCC本身针对Gaussian-wise流水做了固定资源平衡；本课题进一步研究跨场景和跨深度组
  负载变化下，动态资源配置能否提升平均利用率与能效。

## 代价与风险

- 全局深度分组需要先完成所有Gaussian的深度预计算，不能完全消除帧首预处理。
- 多Gaussian并行时存在图像状态RAW依赖，需要有序退休或scoreboard。
- 大Gaussian可能占用block walker较长时间，需要评估切片或多walker，但不能破坏深度提交顺序。
- 全屏图像状态可能超出片上容量；兼容模式可分sub-view顺序处理，但每个sub-view内部仍保持Gaussian-wise。

## 对现有RTL的影响

- `raw_gaussian_projection_lane/array`保留为Gaussian预计算引擎。
- `bbox_tile_bounds_core`保留，bbox用于定义当前Gaussian的块遍历边界。
- `gaussian_tile_task_gen`当前功能保留，语义改为Gaussian内部block walker；后续可重命名。
- `raster_termination_filter`、`alpha_block_float_core`、`image_state_store`和blend链路继续复用。
- 不实现Gaussian–tile bin SRAM和逐tile sort单元。
- 下一批RTL优先级变更为：depth grouper → stable group sorter → ordered issue/retire → Gaussian block walker衔接光栅。
