# 属性交接与投影首次发射旁路

日期：2026-09-14。本轮目标是降低生产计算链的交接/首次发射空拍，扩大真实负载验证，
保持Gaussian-wise固定主路径、动态G/P/R/E、安全epoch、有序退休与完整frame-state等价。
可选并行排序仍默认关闭；这些交接优化不改变排序算法或权重，不增加PE/乘法器。

## 1. 实现与风险控制

`world_to_camera_shared_mac`新增两项默认开启、可独立关闭的模块参数：
`ENABLE_OUTPUT_TURNOVER`在旧XYZ结果退休的同一边沿接受下一输入；
`ENABLE_FIRST_REQUEST_BYPASS`让第一项X轴MAC可在输入接受边沿提交共享P PE。
首次仲裁失败仍接受输入并锁存所有world/rotation/translation/meta，随后RUN状态使用
完全相同的操作数重试。首次成功初始化issued=1、issue_axis=1、acc_valid=110，
响应从axis0/col0开始追踪；其余运算、舍入/饱和、9次MAC/输入、单context均不变。
旧结果被背压时不接收新输入，也不覆盖meta/输出，第一请求旁路不是新增专用MAC。

`ordered_gaussian_attribute_issue`新增默认开启的`ENABLE_OUTPUT_TURNOVER`和
`ENABLE_RESPONSE_BYPASS`。输出已退休时可同边沿提交下一有序attribute请求，仍最多
一笔未完成后端请求；有效live response可直接提交下游，输出背压时捕获同一完整响应，
valid/metadata/data随后从寄存器保持。invalid/unloaded/backend-error不能走旁路。
同边沿response-bypass退休及新request接受时，最后优先保留NEW pending、清OLD
response_available，避免把旧属性误挂在新Gaussian metadata上。

改变的是ready/valid交接与数据选择，不是tile化、场景名单、FIFO容量或计算精度。
增加的输入/响应mux及ready组合路径有实际时序/功耗成本，没有STA/PPA签核。
共享PE仍为G/P一个compare/MAC，R客户端未接，模式资源权重/owner/gate不更改。

## 2. 消融与错误控制

`run_output_turnover_validation.py`分别对XYZ/ATTR执行关闭、仅turnover、turnover+
首次请求/响应旁路三配置，每配置ideal/stressed两个profile，共12项。
XYZ使用实际共享PE及G竞争，每项128输入、1152次P MAC；ATTR使用
延迟后端，每项128请求、121输出、7次错误拒绝，三类sticky error及clear均检查。
source metadata/坐标/属性随接受序号生成，外部仲裁/背压PRNG每个profile固定相同
初始seed，避免不同ideal阶段长度改变下一stressed profile的起点。
每边沿检查停顿输出和请求不变，比较完整数值/meta/flags，不只比较有效数量。

XYZ ideal周期减少255/1536=16.60%；这是持续输入模块，不是整帧加速率。
stressed首次请求29次即时授权、99次失败后重试，总P仍1152，证明cold请求失败合同
实际触发而不是只测理想ready。ATTR ideal最终bypass=121、turnover=0属正常：response
在注册OUT之前已全部退休，后端尚未ready下一请求。首版测试强制此时turnover>0出现
覆盖断言失败，已改为分别核验bypass命中和turnover-only命中，不放宽数据/请求合同。
stressed ATTR最终42次交接、61次live旁路，其余好响应在背压后由寄存器退休。

完整Icarus回归新增2项，最终77自检+1综合入口，258随机XYZ差分、continuation、
AXI晚到错误/恢复、APB快照、四路4类完整帧均保留。Icarus使用SYNTHESIS绕过SVA，
不能称SVA已执行。默认/候选顶层lint及三层级展开检查保持，不以非致命告警当零告警。

排序候选20提速/4持平，单项减少2/3/4/29周期（持平为0）。Garden E/ideal生产及
