# 3DGS动态可重构ASIC系统规格 v0.9

- 日期：2026-08-04
- 状态：Gaussian-wise主数据流正式冻结
- 目标平台：ASIC，SystemVerilog
- 继承：v0.8的数值格式、终止层级、画质与PPA交付要求
- 替代：此前规划的tile/bin缓存与逐tile排序主路径

## 1. 核心研究问题

在相同数值精度、片上容量和片外带宽限制下，GCC式Gaussian-wise有序渲染与
epoch级动态资源配置，能否比固定资源基线获得更高的跨场景利用率和能效，同时保持
正确的前到后透明度混合以及PSNR、SSIM、LPIPS图像质量。

本规格中的“参考GCC”仅指Gaussian-wise执行原则，不代表复制其固定硬件配置。
本课题的核心组合创新是：

```text
Gaussian-wise有序数据流
        +
终止/队列/负载感知的epoch级动态资源重构
```

## 2. 冻结数据流

```text
DRAM Gaussian均值
  → 深度预计算
  → 深度粗分组
  → 组内稳定排序
  → ordered Gaussian issue
  → 按需读取完整Gaussian属性
  → projection + SH + Cholesky描述符
  → Gaussian内部8×8 block walker
  → termination query
  → 64像素alpha/blend
  → 图像状态提交
  → ordered Gaussian retire
```

### 明确禁止的主路径

- 不生成用于长期存储的Gaussian–tile KV对。
- 不建立逐tile Gaussian bin/list。
- 不按屏幕tile扫描并重复加载Gaussian。
- 不在每个tile内部重复执行深度排序。

8×8块仍然存在，但仅作为当前Gaussian内部的空间遍历和64像素并行单位。

## 3. 深度分组与有序发射

- 第一遍只读取Gaussian均值，计算view-space depth并执行near/frustum粗剔除。
- depth被映射到有限数量粗分组；分组按近到远处理。
- 每组执行稳定排序，depth相同时以GID/sequence ID确定唯一顺序。
- 排序输出的是Gaussian ID和depth，不复制完整Gaussian属性。
- ordered issue按顺序读取完整属性并送入投影/SH。
- 前端允许多lane乱序完成，但ordered retire必须恢复全局顺序。
- 更深分组只有在全局/子视图终止条件未满足时才继续处理。

## 4. Gaussian内部块遍历

- projection产生屏幕均值、2D covariance、opacity-aware bbox和Cholesky alpha参数。
- block walker从Gaussian中心附近开始或按保守bbox遍历8×8块。
- 每个块先查询粗粒度终止状态；已终止块不读取像素状态、不执行alpha。
- 未终止块对活跃像素计算alpha、blend并更新64位终止mask。
- 当前Gaussian所有块完成、被安全跳过或为空后，产生Gaussian retire事件。
- `first/last`表示当前Gaussian块序列边界，不表示tile bin边界。

## 5. 顺序与scoreboard

- 基线模式采用严格单Gaussian有序发射/退休，作为正确性参考。
- 优化模式可以让投影、SH或无冲突块并行，但不能改变同像素blend顺序。
- ordered completion buffer保存sequence ID、完成状态和描述符引用。
- block scoreboard仅用于隐藏不同块的延迟；同块/同像素前驱未提交时必须停顿。
- scoreboard不能把后继Gaussian提交到前驱之前，也不能扩大提前终止范围。

## 6. 动态模式

动态配置候选包括：

- 1/2/4条projection lane；
- SH并行度；
- Gaussian block walker或alpha资源份额；
- 排序/投影/光栅队列容量份额；
- 兼容模式下的sub-view尺寸。

模式只在epoch边界且所有受影响队列、lane、ordered retire和scoreboard安全排空时提交。
策略以长窗口计数器和滞回决策，禁止逐Gaussian切换。

### 6.1 重构对象

- **算术lane启停**：projection 1/2/4 lane，后续SH和alpha也采用可复制lane。
- **共享算术复用**：帧首depth/group阶段与后续projection/SH阶段时分复用比较器、MAC或divider。
- **调度权重**：改变group/sort、projection、SH、block raster队列的服务优先级。
- **存储份额**：在总SRAM固定的条件下改变group目录、ordered completion、Gaussian描述符和
  block任务队列的bank/容量份额。
- **时钟门控**：对未启用lane和空闲bank门控，形成低功耗模式。

### 6.2 运行时观测量

- 每组Gaussian数量、分组溢出、sort busy周期；
- projection输入/输出队列水位、lane busy和数值回退数量；
- 每Gaussian候选块、有效块、终止跳过块和平均块数；
- alpha发射、alpha裁剪、blend提交、scoreboard等待；
- ordered retire等待、外存读写停顿及各阶段空闲周期。

### 6.3 模式建议与提交

1. 饱和计数器在一个或多个深度组/子视图组成的长窗口内统计负载。
2. 策略器只输出`recommended_mode`，不直接改变硬件状态。
3. 滞回与最短驻留时间过滤短时波动。
4. 模式写入shadow寄存器。
5. 只有安全epoch边界才原子提交active配置。

### 6.4 公平基线

- 固定G、固定P、固定R及固定单lane模式均作为静态基线。
- 动态方案与各固定基线使用相同物理资源上限、SRAM总量、DRAM带宽、时钟和数值格式。
- 必须同时报告逐场景最优固定模式、单一全局固定模式和动态模式，防止只挑有利基线。
- 动态控制器自身的面积、功耗、排空与切换开销必须计入PPA和周期结果。

## 8. 验收要求

- 固定基线和动态模式使用同一Gaussian顺序、数值路径、存储与带宽限制。
- 逐事务验证深度分组无丢失/重复，组间近到远，组内稳定排序。
- 验证多lane乱序完成不会导致blend乱序。
- 验证一颗Gaussian全部块完成后才退休，背压下first/last稳定。
- 真实场景报告属性加载次数、KV流量消除量、排序工作量、块/像素跳过率和吞吐。
- 完整图像报告PSNR、SSIM、LPIPS。
- 在明确工艺节点、标准单元库、SRAM宏、PVT、频率和真实活动下报告面积与功耗。
