# 3DGS动态可重构ASIC完整RTL交付分解 v0.1

- 日期：2026-08-04
- RTL语言：SystemVerilog
- 目标：毕业设计提交可综合的完整加速器RTL，而非只提交关键算子
- 当前边界：工艺无关实现优先；工艺库、SRAM宏和综合工具就绪后再冻结具体节点PPA
- 版本状态：已由`完整RTL交付分解_v0.2.md`替代；v0.2明确删除Gaussian–tile bin和逐tile排序主路径。

## 1. 交付定义

“完整RTL”至少包括从命令接收、模型与相机数据搬运、投影、分组/排序、SH颜色、块任务生成、alpha、blend、图像状态、提前终止、动态模式控制、性能计数到结果写回的闭环。外部DRAM和主机CPU不在RTL内部实现，但其总线端点、寄存器映射和DMA主控必须提供。仿真专用代码与综合RTL分目录管理。

## 3. 建议的实现顺序

1. 冻结顶层事务格式、寄存器表和抽象SRAM接口。
2. 完成块任务、scoreboard、图像状态和blend的整数/定点闭环。
3. 解决超大投影高斯的alpha数值表示，随后实现alpha流水RTL。
4. 完成投影、SH、排序和DMA，使端到端渲染不再依赖软件预处理。
5. 接入模式控制和性能计数，建立固定基线与动态方案的同RTL切换。
6. 使用真实场景完成图像质量、吞吐与流量验证。
7. 在具体工艺节点执行综合、SRAM编译/替换、STA和功耗分析。

## 4. 强制最终验收

- 完整SystemVerilog源代码、综合文件清单、约束、仿真与SVA。
- 至少一个固定功能基线和一个终止感知动态模式共用同一数值精度与外存接口。
- 真实场景端到端图像，报告PSNR、SSIM、LPIPS；同时区分相对FP32渲染和相对数据集GT两套评价（若GT可用）。
- 指定工艺节点、标准单元库、SRAM宏、PVT、时钟与活动文件下的面积、频率、动态/漏电功耗和能量/帧。
- 报告工具版本、关键约束、未决warning和不可比较项，禁止用抽象“资源额度”替代面积。

## 5. 当前阻塞但不妨碍工艺无关开发的输入

- 具体工艺节点、标准单元库、SRAM编译器/宏、综合与功耗工具尚未准备，因此现在不能给出可信面积与功耗数值。
- 本地运行时缺少PyTorch、LPIPS包和预训练权重；PSNR/SSIM入口已具备，LPIPS计算需后续离线准备依赖。
- 当前13个场景目录仅发现训练输出模型/相机，未发现标准`images`目录；若论文需要相对GT图像评价，需要补充对应测试图像。没有GT时可先以FP32软件渲染作为数值质量基准。
